# CloudBase 优化与拍卖暂停超时：交付记录

分支：dev。以下为本地实现阶段记录；后续体验环境已发布并验收，最新状态及验证边界见 [体验环境发布记录](../../deployment/2026-10-30-staging-resource-release.md)。原有后台/合同文件的用户改动未纳入该体验环境 API 发布包；本次按用户要求统一提交当前源码和文档。

## 已实现

- 拍卖空闲扫描从 500 ms 降为 5 秒；活跃拍卖仍为 500 ms。启动、继续、恢复操作保留 120 秒检查窗口，避免提交前空读使短倒计时被延迟。
- 估值窗口空闲检查间隔为 30 秒，同时按下一次开窗边界唤醒；窗口修改后唤醒，后台任务不重叠，停止时等待在途任务。请求时和阵容变更前的快照保护保持原有逻辑。
- 手动暂停、异常暂停连续达到 1 小时后自动取消批次。独立 pausedAt 保留暂停起点；暂停转异常恢复不重置计时，成功恢复后清空，下次暂停重新计时。
- 超时恢复在数据库时间下被拒绝；独立每 5 秒扫描通过有序行锁复核，再事务化作废未结束拍品、取消批次并写审计。已结束和待审核结果、资金、阵容保留。
- 新增迁移 20261030120000_auction_pause_timeout 和状态/暂停时间索引。

- 小程序：100 files、468 tests 通过。
- 后台：59 files、266 tests 通过（maxWorkers=2）。
- 合同测试：工作区 pnpm test 中通过。
- 指定端到端：4 suites、9 tests 通过，覆盖拍卖、估值、联赛球队、联赛生命周期/我的联赛。
- 新增边界覆盖：空闲读预算、活跃频率、短剩余时间恢复后的提交空读、开窗边界实际初始化、在途停机/失败重试、1 小时前后、手动暂停转异常、重复取消、恢复赢得锁竞争、正常恢复后再次暂停。

- 所有 API 测试显式指定 127.0.0.1:33316 的 efm_cloudbase_verify / efm_cloudbase_e2e_verify。两库均为本次新建的独立 mysqld 数据目录，使用 fake 微信网关和本地临时上传目录，未在共享库执行测试。

排查并解决的验证问题：隔离库初始缺少基础角色 seed、主机时区与测试时间不一致；旧倒计时文案断言；新超时系统审计需要加入测试清理；测试夹具类型及既有 lint 未使用符号；后台高并行测试超时（单独及低并行全量通过）；构建与测试并行生成 Prisma 引发两项临时 ENOENT（停止并行生成后 API 全量通过）。

## 审查结论与发布限制

独立审查已完成。实现未发现剩余功能问题；发现新旧版本混跑会漏写/沿用 pausedAt 的发布风险，已落实为 docs/deployment/cloudbase.md 的受控发布约束：迁移前冻结拍卖控制写入、停止旧拍卖任务并等待在途事务，迁移后全量切换新代码再开放。不能在旧版本继续写入时仅执行迁移。

历史手动暂停缺乏独立时间戳，迁移使用 updated_at 保守回填，可能比真实暂停起点晚；历史异常暂停优先使用 recovery_detected_at。发布前应核对迁移后会自动取消的历史批次。

线上数据库迁移状态、实际接口及微信开发者工具线上预览尚未验证；未修改 CloudBase 实例规格、伸缩配置、CDN或压缩设置。需要上线后比较 CCU 和空闲查询、CPU/内存峰值、接口延迟及出网路径，不能把查询降幅等同账单降幅。
