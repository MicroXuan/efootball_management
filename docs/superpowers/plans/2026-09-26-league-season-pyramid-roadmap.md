# 联赛赛季体系实施路线图

> 当前状态（2026-10-04）：四个赛事阶段及资产、财务、身价、交易和收藏模块均已进入当前代码。本文保留阶段拆分与验收边界；当前完整需求状态以[实况足球需求路线图](../specs/2026-10-02-efootball-requirements-roadmap.zh-CN.md)为准。

**目标：** 在不破坏现有个人赛事闭环的前提下，把系统逐步升级为“长期联赛 → 多赛季 → 分级联赛与多杯赛”的运营平台。

**产品规格：** [联赛、赛季、分组与杯赛体系设计](../specs/2026-09-26-league-season-pyramid-design.zh-CN.md)

## 实施原则

- 保留现有 `Competition`、报名、赛程、比分版本、双方确认和积分计算能力。
- 先建立长期身份和赛季资格，再接入分组算法、杯赛和聚合界面。
- 新旧数据并行读取；旧 Competition 在完成兼容回填前不强制绑定赛季。
- 所有关键写操作使用幂等键、乐观版本和审计记录。
- 赛季报名使用 `TeamProfile` 的快照，历史展示不读取可变的长期球队资料。
- 系统建议和管理员正式决定分离保存，不用自动算法直接覆盖正式分组。
- 本路线图最初只为经营能力预留边界；资产、财务、身价、交易和收藏现已在后续需求批次中实现，工资帽仍保留独立扩展边界。

## 阶段 1：联赛基础

**阶段状态：** 代码、迁移、Native 页面与自动化验证已完成；微信开发者工具的玩家/管理员双身份手工回归仍按[本地验收指南](../../league-foundation-local-verification.zh-CN.md)执行。

**交付物：** `League`、`TeamProfile`、`LeagueSeason`、`SeasonEntry`、报名与续赛闭环。

### 能力范围

- 联赛创建、编辑、公开列表和详情。
- 一名微信用户一个长期球队档案；绑定默认游戏账号。
- 赛季创建并继承联赛默认容量规则，允许赛季覆盖。
- 赛季生命周期：`DRAFT → REGISTRATION_OPEN → ALLOCATION_REVIEW`，以及取消。
- 创建后续赛季时，自动为上一赛季正式成员建立续赛邀请。
- 老成员确认续赛后直接获得正式资格；新成员提交申请后由管理员审核。
- 赛季资格保存球队名称、队徽和游戏账号快照。
- 联赛/赛季作用域权限向下授权所需的基础解析能力。
- Native 小程序可维护球队档案、浏览联赛和赛季、报名/续赛、审核报名。

### 验收出口

- 首赛季可以从零完成新报名与审核。
- 下一赛季开放报名时能生成续赛邀请，未确认者不会进入正式名单。
- 报名截止后普通用户不能报名、确认或撤回。
- 同一联赛不能出现两个 `IN_PROGRESS` 赛季；该约束在阶段 1 先建立数据库/领域能力，在阶段 2 开放开始赛季操作时验收。
- 现有 Competition API 与小程序赛事页面仍可工作。

详细执行计划见 [联赛基础实施计划](./2026-09-26-league-foundation-implementation-plan.md)。

## 阶段 2：分级联赛

**交付物：** 首赛季规则、超级组/冠军组、分组建议、单循环赛程、Stage 级积分榜和升降级建议。

### 能力范围

- `Competition` 增加可空 `seasonId` 与 `competitionType`，旧赛事继续兼容。
- `CompetitionStage` 表达 `SUPER`、`CHAMPION_A/B/C` 等组别。
- `StageParticipant` 保存正式阶段分配。
- 首赛季只生成冠军组；19、25、36、37 等规模按容量均分。
- 第二赛季起支持超级组目标容量、蛇形冠军分组和新队随机均布。
- `AllocationProposal/Row/Decision` 保存建议、算法版本和管理员调整原因。
- 单循环奇数轮空；23 人生成 23 轮、每队 22 场。
- `StandingsSnapshot` 下沉到 Stage，各组独立排名。
- 完成分组后才能生成赛程，发布赛程后锁定阶段成员。

### 验收出口

- 首赛季永远没有超级组。
- 各冠军组人数差不超过 1。
- 系统只给建议，管理员确认才写正式阶段成员。
- 超级组、冠军 A/B/C 的赛程和积分互不混算。
- 旧 Competition 的比赛数和官方比分版本不变。

## 阶段 3：杯赛体系

**交付物：** 多杯赛、自主报名、足总杯小组赛和淘汰赛。

### 能力范围

- 一个赛季创建多项独立 Competition。
- 仅正式 `SeasonEntry` 可以报名本赛季杯赛。
- 足总杯按默认每组 4 人随机均分，管理员确认后发布小组赛。
- 每组默认前 2 名出线，生成第一档/第二档淘汰签表。
- 首轮尽量同组回避，非标准人数自动生成轮空建议。
- 其他杯赛可配置纯淘汰或小组加淘汰。
- 杯赛未完成或未取消时，禁止完成所属赛季。

### 验收出口

- 杯赛报名不会影响分级联赛积分。
- 小组赛未完成时不能发布正式淘汰签表。
- 重抽签生成新建议版本，不静默覆盖已发布签表。

## 阶段 4：聚合体验

**交付物：** 面向玩家和管理员的完整 Native 联赛体验。

### 能力范围

- 底部导航调整为“球员｜联赛｜我的”。
- 联赛首页聚合当前赛季、我的组别/排名/下一场、杯赛状态和历史赛季。
- 赛季积分榜在超级组、冠军 A/B/C 间切换。
- 杯赛中心显示小组积分和淘汰签表。
- 我的比赛聚合分级联赛与所有杯赛。
- 管理工作台聚合报名、分组、赛程、签表、比分和审计入口。
- 功能宫格基于模块配置和权限渲染，为资产、财务、身价、工资帽和收藏预留入口。

### 验收出口

- 普通用户在一个联赛页面完成报名、看榜、看赛程和看杯赛。
- 管理员不必进入多个割裂页面即可推进一个赛季。
- 不展示虚假的跨组正式总排名。

## 独立模块当前状态

赛季资产与阵容、财务流水、身价版本与交易、球员卡筛选与收藏均已按后续规格实现，并继续引用 `League`、`LeagueSeason`、`TeamProfile` 和 `SeasonEntry`，没有重新定义球队或赛季身份。

工资帽的完整约束闭环，以及比赛截图 OCR、申诉、处罚和微信订阅消息仍属于独立扩展范围；它们不计入当前 PDF 需求的 R1–R12 验收。
