# 球员包筛选摘要设计

日期：2026-10-23
状态：已由用户改为“筛选项不显示张数”；本方案存档，不再执行。现行方案见 [球员包轻量选项](2026-10-23-player-pack-options.zh-CN.md)。

## 现状与目标

小程序“球员库”打开时请求 `/v1/card-packs?limit=100`，筛选项显示包名和准确卡片数；后台“球队阵容 → 购买球员”打开时请求同一接口，只显示包名。当前接口每次从所有球员卡历史版本判断最新有效版本，再按包分组、计数、排序。5 万张卡、10 万条版本的本机基准中，球员包列表 p50 约 0.55 秒，p95 在 12 次样本中约 3.46 秒。两处客户端都只取第一页，超过 100 个包时会漏掉后续筛选项。

目标：保留现有 `/v1/card-packs` 响应形状、准确数量、排序、固定发布序号游标、空包隐藏规则；新查询读取包级摘要，避免每次扫描全部卡片。小程序和后台都能取得全部可选球员包。

## 数据模型与读写路径

```mermaid
flowchart LR
  A[管理员发布一个球员卡批次] --> B[找出旧包和新包]
  B --> C[只重算受影响的包]
  C --> D[(包摘要版本：包ID + 发布序号)]
  D --> E[球员库筛选 / 后台购买筛选]
  E --> F[包名 + 准确卡片数]
```

新增 `catalog_pack_summary_versions`：主键 `(card_pack_id, release_sequence)`；记录 `card_count`、`newest_version_id`。每个发布批次只给**受影响的包**写一条摘要版本；卡片下架、换包后若旧包变空，也写 `card_count = 0` 的版本，避免错误回退到旧的非空摘要。`newest_version_id` 指向该包在当次发布快照中按现有规则排第一的有效卡版本，包名、日期、封面和排序仍从这条不可变版本读取，不使用可能已变化的 `card_packs` 当前值。

发布事务中，在新增球员卡版本后，集中查询受影响包在本发布序号下的最新有效卡，生成计数与代表版本；摘要与球员卡版本一起提交或一起回滚。受影响包集合来自本批卡片的**旧包 ID 和新包 ID**，包括新增、更新、下架和换包。对未受影响的包，读取不晚于游标发布序号的最新摘要版本即可。

新增单行投影进度 `catalog_pack_summary_projection_state.projected_through_sequence`。读接口只在进度覆盖所请求发布序号时使用摘要；否则回退到现有动态 SQL，以保证过渡期间正确性。新发布事务在写摘要后推进进度；发布前锁定这行以串行化发布序号和摘要计算。当前后台“全量发布”本来逐批顺序执行，因此此锁主要防止多个管理员同时发布造成快照交错。

包列表以 `card_packs` 为候选集合，针对每个包用 `(card_pack_id, release_sequence)` 索引读取不晚于固定发布序号的最近摘要；过滤 `card_count = 0`，关联 `newest_version_id` 排序并分页。最多把 `limit + 1` 个包返回 Node.js。详情 `/v1/card-packs/:id` 继续按指定包读取卡片，不依赖摘要计数。

## 历史回填与上线

现有共享库只读核对为 8 次发布、27 个包、200 张卡、205 条版本；新增表上线时先对每个历史发布序号按顺序建立受影响包摘要。回填工具可 dry run、可按序号续跑，最后对每个历史快照校验摘要数量、空包、代表卡及包排序。先暂停发布，部署迁移和回填；部署全部能写摘要的 API 实例后复查进度，再放行发布和摘要读取。若进度落后，接口自动回退原 SQL，不返回不完整包列表。

小程序与后台改为按 `nextCursor` 读取全部球员包选项，同一次加载保持游标所固定的发布快照。小程序仍显示“包名 · N 张”；后台仍只显示包名。若未来包数增长到原生选择器难以使用，再单独设计远程搜索，不在本次改变交互。

## 验收边界

- 数量是发布快照内“最新版有效卡”的数量；同一张卡的历史版本不重复计数，已下架卡不计数。
- 新增、换包、下架、同名不同包、空包、连续多批发布和发布中翻页均与现有动态 SQL 一致。
- 回填及测试只在显式指定的本机隔离 `test/verify` 库写入；共享库只读核对迁移状态，受控上线时先迁移、回填再切流量。
- 在 5 万张卡、多版本、至少 500 个包和多次发布的隔离基准中，每项预热后至少测 100 次，报告首页、深页、筛选、包列表 p50/p95 及 `EXPLAIN`；以包列表 p95 低于 100 毫秒作为本机目标，再于目标环境确认实际表现。
