# 平台 PESDATA 数据同步中心设计

## 1. 背景

当前 PESDATA 同步能力分散在两个位置：

- 球员卡同步主要通过后端命令执行，平台管理员无法在浏览器中直接启动、查看进度和发布；
- 球队队壳同步入口放在某个联赛的“用户与球队”页面，容易让人误解为仅服务当前联赛，并且大量同步明细会挤占日常联赛管理空间。

PESDATA 球员卡和球队队壳都属于平台级公共数据，不属于任何单一联赛。因此本次将两类能力收口到独立的“数据同步”模块，由平台管理员统一操作。联赛工作区只保留用户、经营球队和队壳分配等联赛业务。

## 2. 目标

- 平台侧新增独立的“数据同步”模块；
- 同一页面通过“球员卡”和“球队队壳”两个页签管理两类同步；
- 平台管理员可以在浏览器中启动抽样、增量和全量同步；
- 同步启动后立即返回任务编号，页面持续展示进度，不要求浏览器一直保持连接；
- 同步结果先进入待审核区，管理员确认后才发布到正式目录；
- 大数据量场景采用汇总、异常优先、筛选和服务端分页，不一次渲染全部记录；
- 发布、拒绝、重试等操作支持单条和批量处理；
- 进程中断或来源站异常后能够明确失败并从检查点恢复；
- 所有操作产生具体、可理解的审计日志，不再出现“其他后台操作”。

## 3. 非目标

- 不让浏览器或小程序直接请求 PESDATA；
- 不把同步入口继续放在任一联赛工作区；
- 不自动发布同步得到的新数据或变化；
- 不因来源数据暂时缺失而自动删除正式球员卡或球队队壳；
- 不把平台管理员伪装成普通用户来复用普通用户令牌；
- 不在本阶段增加定时自动同步，仍由平台管理员手动启动；
- 不改变球队队壳与经营球队阵容相互独立的既有规则。

## 4. 信息架构与权限

### 4.1 导航与路由

平台管理侧边栏新增：

```text
数据同步
```

建议路由：

```text
/platform/data-sync
```

页面包含两个页签：

```text
球员卡 | 球队队壳
```

从联赛“用户与球队”页面删除现有的 `PESDATA 队壳同步` 卡片。该页面仍可搜索和选择已经发布的本地队壳，但不负责从外部来源同步。

### 4.2 权限边界

只有平台管理员可以查看和操作数据同步中心。所有新接口使用后台管理员认证 `AdminAuthGuard`，并显式校验 `platformAdmin = true`。

现有球员导入接口使用普通用户 JWT 和 `catalog.import.*` 权限，不能直接给平台管理网页使用。实现时把“同步、生成导入批次、发布”的领域逻辑与入口授权拆开：

- 普通用户入口继续使用现有 `JwtAuthGuard` 与 scope 权限；
- 平台同步入口使用 `AdminAuthGuard` 与平台管理员身份；
- 两个入口调用相同的内部领域操作，但各自在控制器或应用服务边界完成授权；
- 不生成虚假的普通用户令牌，也不借用普通用户账号执行平台同步。

审计日志是平台操作人身份的权威记录。同步运行和导入批次现有的字符串操作人字段可继续保存管理员 ID；本阶段不为此单独引入数据库外键迁移。

## 5. 页面总体设计

页面采用“任务概览 + 当前任务 + 待处理数据 + 历史任务”四层结构，避免把几百或几万条同步明细直接铺满页面。

### 5.1 顶部概览

顶部展示当前页签对应的统计卡：

- 来源扫描总数；
- 新增；
- 更新；
- 待确认缺失；
- 待发布；
- 已发布；
- 失败。

统计值来自后端聚合接口，不由前端加载全部数据后计算。

### 5.2 启动同步

页面提供三个入口：

- 抽样同步：用于协议和字段验收，默认少量数据；
- 增量同步：日常使用，只处理新增、变化和上次失败的数据；
- 全量同步：遍历全部来源数据。

全量同步必须二次确认，并明确提示预计耗时较长、不会自动发布。若同类数据已有活动任务，禁止重复启动并跳转到当前任务。

### 5.3 当前任务

任务卡展示：

- 任务编号、模式和状态；
- 启动人、开始时间、最近更新时间；
- 已扫描/来源总数、成功、跳过、失败；
- 当前阶段，例如“读取列表”“获取详情”“校验图片”“生成审核批次”；
- 最近错误摘要；
- 失败或中断后的“继续任务”入口。

活动任务期间前端每 2 至 3 秒轮询状态；页面离开后任务继续运行。任务到达终态后停止轮询并刷新统计和待处理列表。

### 5.4 大量数据的展示原则

默认展示“待发布”和“失败”，已发布记录折叠到筛选项中，避免历史成功数据淹没需要处理的问题。

表格必须使用服务端筛选、排序和分页：

- 每页默认 20 条，可切换 20/50；
- 支持状态、新增/更新类型、来源联赛等筛选；
- 支持名称、简称、来源 ID 搜索；
- 返回当前筛选下的总数；
- 切换筛选或页码时只请求当前页；
- 失败项支持按错误原因聚合，点击原因后进入对应筛选结果；
- 单击记录打开侧边详情抽屉，不在列表内展开大段原始数据。

不提供“全部加载”按钮，防止球员卡全量同步时把数万条记录送到浏览器。

### 5.5 批量操作

表格支持跨当前页勾选的批量操作，但只对当前筛选结果中明确选中的记录生效：

- 批量发布；
- 批量拒绝；
- 批量重试失败项。

批量操作前展示数量和影响摘要，操作后返回成功数、跳过数和失败数。部分失败不能伪装成全部成功，失败记录保留在当前筛选中。

“发布当前筛选全部结果”属于高风险操作，本阶段不提供，避免误发布数万条记录。

## 6. 球员卡页签

### 6.1 同步和审核链路

```text
平台管理员启动同步
        ↓
ExternalSyncRun 异步执行并保存检查点
        ↓
生成一个或多个 ImportBatch
        ↓
管理员分页查看有效/无效记录和变化
        ↓
逐批或批量发布
        ↓
正式球员卡目录
```

同步沿用现有 PESDATA 客户端、映射器、运行记录和导入批次，不创建第二套球员数据管道。

### 6.2 列表字段

球员卡审核表建议显示：

- 球员头像或卡图缩略图；
- 球员名；
- 卡片类型/卡包；
- 位置与总评；
- 来源 ID；
- 变化类型：新增、更新、无变化；
- 校验状态；
- 发布状态；
- 最后错误；
- 操作。

详情抽屉展示完整属性、技能、来源摘要、字段变化对比、原始校验错误和关联导入批次。

### 6.3 发布粒度

保持现有导入批次语义。列表可以按记录筛选和查看，但正式发布仍以 `ImportBatch` 为事务边界，避免只发布半个批次导致版本和校验逻辑失效。

界面上的“批量发布”实际选中一个或多个可发布批次；若管理员从记录列表发起，前端先汇总受影响批次并要求确认。无效记录存在时沿用现有发布规则，不绕过校验。

## 7. 球队队壳页签

### 7.1 同步和审核链路

```text
平台管理员启动同步
        ↓
TeamCatalogSyncRun 异步执行并保存检查点
        ↓
生成 TeamCatalogSyncItem 差异
        ↓
队徽下载、校验并保存到自有对象存储
        ↓
管理员分页审核并发布/拒绝
        ↓
TeamCatalogItem 正式队壳目录
```

### 7.2 列表字段

球队队壳审核表建议显示：

- 队徽缩略图；
- 球队名称与简称；
- 来源联赛；
- 来源球队 ID；
- 变化类型：新增、更新、待确认缺失；
- 队徽处理状态；
- 发布状态；
- 最后错误；
- 操作。

详情抽屉展示同步前后名称、简称、队徽对比，来源地址、自有存储地址、校验值和错误详情。

### 7.3 发布规则

- 新增队壳发布后进入全平台本地队壳目录；
- 更新队壳发布后更新目录版本，但不自动覆盖已经分配给经营球队的展示快照；
- 来源缺失只标记 `SOURCE_UNCONFIRMED`，不自动删除、禁用或释放队壳；
- 队徽下载或校验失败时不能发布该条记录；
- 自定义队壳不属于 PESDATA 同步范围，继续在联赛创建/编辑球队流程中使用。

## 8. 后端接口

所有接口位于 `/v1/admin/data-sync`，统一使用平台管理员认证。

### 8.1 总览

```text
GET /v1/admin/data-sync/overview
```

返回球员卡与球队队壳的活动任务、待处理数、失败数和最近完成时间，用于侧边栏提示和页面首屏。

### 8.2 球员卡同步

```text
POST /v1/admin/data-sync/players/runs
GET  /v1/admin/data-sync/players/runs
GET  /v1/admin/data-sync/players/runs/:runId
POST /v1/admin/data-sync/players/runs/:runId/resume
GET  /v1/admin/data-sync/players/runs/:runId/batches
GET  /v1/admin/data-sync/players/batches/:batchId/records
POST /v1/admin/data-sync/players/batches/:batchId/publish
POST /v1/admin/data-sync/players/batches/:batchId/reject
```

创建任务请求包含 `mode: sample | incremental | full` 和抽样上限等必要参数，成功返回 `202 Accepted` 与 `runId`。

### 8.3 球队队壳同步

```text
POST /v1/admin/data-sync/teams/runs
GET  /v1/admin/data-sync/teams/runs
GET  /v1/admin/data-sync/teams/runs/:runId
POST /v1/admin/data-sync/teams/runs/:runId/resume
GET  /v1/admin/data-sync/teams/runs/:runId/items
POST /v1/admin/data-sync/teams/items/:itemId/publish
POST /v1/admin/data-sync/teams/items/:itemId/reject
POST /v1/admin/data-sync/teams/items/publish
POST /v1/admin/data-sync/teams/items/reject
POST /v1/admin/data-sync/teams/items/retry
```

批量接口接收明确的项目 ID 数组，并设置合理上限，例如单次最多 100 条。超过上限时拒绝请求，不静默截断。

### 8.4 分页响应

列表接口统一接收：

```text
page
pageSize
status
changeType
sourceLeagueId
errorCode
query
sortBy
sortOrder
```

统一返回：

```json
{
  "items": [],
  "page": 1,
  "pageSize": 20,
  "total": 0,
  "summary": {}
}
```

`pageSize` 只允许 20 或 50。筛选、排序字段采用白名单，搜索词设长度上限，避免把前端参数直接拼入数据库查询。

## 9. 异步执行与恢复

### 9.1 执行模型

项目当前没有独立队列基础设施，本阶段采用数据库运行记录与检查点驱动的本地后台执行器：

1. 接口在事务中创建 `PENDING` 运行记录；
2. 提交事务后把运行交给后台执行器；
3. 接口立即返回 `202`，不等待远端同步完成；
4. 执行器获取数据库租约后改为 `RUNNING`；
5. 每页或每个稳定批次更新检查点与统计；
6. 完成后进入 `READY`，异常进入 `FAILED` 或可恢复状态。

同一资源类型同一时间只允许一个活动任务。球员卡和球队队壳可以分别判断租约，首版界面仍建议一次只执行一个外部同步，降低对 PESDATA 的压力。

### 9.2 进程重启

应用启动时检查遗留的 `RUNNING` 任务：

- 租约仍有效时不重复领取；
- 租约过期且检查点完整时标记为“已中断，可继续”；
- 管理员点击继续后从检查点恢复；
- 已成功的页面、详情、图片和批次不得重复写入；
- 协议错误、授权错误等不可恢复故障必须先解决原因，不能无限自动重试。

本阶段不保证服务器重启后自动继续长任务，保证的是任务状态不丢失、可以安全人工恢复。

## 10. 审计日志

每个操作使用具体中文动作名：

- 启动球员卡抽样同步；
- 启动球员卡增量同步；
- 启动球员卡全量同步；
- 继续球员卡同步；
- 发布球员卡导入批次；
- 拒绝球员卡导入批次；
- 启动球队队壳抽样同步；
- 启动球队队壳增量同步；
- 启动球队队壳全量同步；
- 继续球队队壳同步；
- 发布球队队壳；
- 批量发布球队队壳；
- 拒绝球队队壳；
- 批量拒绝球队队壳；
- 重试球队队壳同步失败项。

审计元数据至少包含资源类型、运行/批次/项目 ID、模式、选择数量、成功数、失败数和错误代码。日志描述必须能说明管理员实际做了什么，禁止回退到“其他后台操作”。

## 11. 错误处理

页面把错误分为：

- 网络或限流错误：允许重试；
- 来源服务错误：允许稍后重试；
- 协议或签名错误：整次任务失败，需要修复适配器；
- 字段映射错误：保留单条失败，其他记录继续；
- 图片下载或校验错误：球队队壳单条失败；
- 发布校验错误：不写正式目录，并返回具体字段；
- 并发任务冲突：跳转到已经运行的任务。

前端展示用户可理解的中文摘要，同时保留错误代码、来源 ID 和最近一次技术错误供排查。敏感签名、Cookie 和完整响应不能进入接口响应或审计日志。

## 12. 数据库与兼容性

本阶段优先复用现有：

- `ExternalSyncRun`、`ExternalSyncItem`、`ExternalSyncRunBatch`；
- `ImportBatch` 及现有球员发布表；
- `TeamCatalogSyncRun`、`TeamCatalogSyncItem`；
- `TeamCatalogItem`；
- `AuditLog`。

若现有运行表缺少租约到期时间、当前阶段或最近心跳字段，实现阶段只补充异步恢复必需的最小字段迁移。不得为页面统计复制一套事实数据；统计应从运行、项目和批次表聚合。

现有 CLI 同步命令继续保留，作为维护和故障恢复工具；网页入口与 CLI 使用同一同步服务和互斥租约，不能同时创建重复任务。

## 13. 测试与验收

### 13.1 后端测试

- 非平台管理员无法访问新接口；
- 平台管理员可以创建三种模式的任务；
- 创建任务立即返回，不等待同步完成；
- 同类活动任务不能重复启动；
- 任务进度和检查点持续保存；
- 进程中断后可以安全继续且不重复写入；
- 分页、筛选、搜索、排序和总数正确；
- 20/50 以外的分页大小被拒绝；
- 球员卡发布保持导入批次事务边界；
- 队壳批量发布、拒绝和重试正确处理部分失败；
- 来源缺失不会删除正式数据；
- 每种管理操作产生具体审计动作；
- 现有 CLI 和普通用户导入接口不回归。

### 13.2 前端测试

- 平台侧出现“数据同步”，联赛工作区不再显示同步卡片；
- 两个页签状态、筛选和 URL 行为稳定；
- 默认只看待发布和失败项；
- 表格只加载当前页，切换 20/50 正确；
- 任务运行时轮询，终态后停止；
- 页面刷新后能够恢复当前任务展示；
- 详情抽屉显示前后差异与错误；
- 全量和批量操作均有明确确认；
- 空状态、加载状态、失败状态和部分成功状态均可理解。

### 13.3 人工验收顺序

1. 启动球员卡抽样同步并离开页面，再返回确认任务仍在执行；
2. 查看待审核批次、无效记录和变化详情，发布一个测试批次；
3. 启动球队队壳抽样同步，确认队徽保存到自有对象存储；
4. 发布一条新队壳，在联赛创建球队时搜索到该队壳；
5. 验证默认列表不铺满已发布历史记录；
6. 验证失败原因聚合、筛选和重试；
7. 模拟服务重启，确认任务显示为可继续且恢复后不重复处理；
8. 检查审计日志中的动作名称和操作详情。

## 14. 实施顺序

1. 抽取平台管理员可调用的同步与发布应用服务，明确两套认证边界；
2. 补齐异步运行、租约、检查点和启动恢复逻辑；
3. 新增平台数据同步接口及服务端分页；
4. 新增“数据同步”导航、页面与球员卡页签；
5. 迁移球队队壳同步 UI，并从联赛页面移除旧卡片；
6. 增加批量操作、异常聚合和详情抽屉；
7. 补齐具体审计动作、自动化测试和运维文档；
8. 依次完成抽样、重启恢复、增量和全量验收。

## 15. 已确认决策

- PESDATA 球员卡同步和球队队壳同步独立于联赛工作区；
- 使用一个平台级“数据同步”模块，通过两个页签区分数据类型；
- 平台管理员可以直接从浏览器启动、查看进度和发布；
- 默认使用增量同步，抽样用于验收，全量需要二次确认；
- 同步数据先审核后发布；
- 大数据量默认异常优先，采用服务端分页和筛选；
- 球员卡以导入批次为发布事务边界；
- 球队队壳更新不自动覆盖已分配经营球队的展示快照；
- 页面离开不终止任务，进程重启后支持从检查点人工继续；
- 所有审计日志必须使用具体操作内容。
