# 轻量待办中心规格

## 目标

在不增加底部 Tab、不复制原业务页面的前提下，为已登录用户提供跨联赛待办汇总，并把普通交易、强报与小程序拍卖状态接入提醒和角标。

## 信息架构

- 主入口：`我的 Tab → 待办中心`。
- 联赛入口：`联赛详情 → 我的联赛工作台` 显示当前联赛待办数量，并跳转至按联赛筛选的待办中心。
- 原业务入口：球员市场、球员拍卖保留实际操作能力；待办项只负责说明状态并深链跳转。
- 底部导航保持 `球员 / 联赛 / 我的` 三项；“我的”仅在存在需处理事项或未读状态更新时显示小角标。

## 待办来源

- 普通交易：我的购买申请待处理、需重新报价、审核结果等状态。
- 强报：我发起的强报状态，以及针对我球队球员的待处理强报。
- 球员拍卖：等待开始、进行中、暂停或待恢复的小程序拍卖。

## 展示规则

- `待我处理`：需要用户当前采取行动的事项，例如重新报价、进入正在进行的拍卖。
- `状态更新`：无需立即操作但需要知晓的变化，例如申请审核结果、收到强报。
- `近期记录`：仍在合理时间窗口内的已结束业务状态。
- 已读状态保存在小程序本地，以 `待办 ID + 版本时间` 识别一次状态变化；服务端业务状态始终是事实来源。
- 打开待办中心即把本次加载到的状态更新标为已读；仍需用户处理的事项即使已读，也继续计入待办角标。

## 约束

- 不新增聊天、动态流或第四个底部 Tab。
- 不复制交易、强报、拍卖的操作表单。
- 不引入新的数据库表；第一版从现有业务数据实时投影待办。
- 单个待办必须能跳转到现有业务页面。
- 空状态、网络失败、没有球队和没有当前赛季时均应安全显示。
