# 赛果确认、争议取证与管理员仲裁设计

## 目标

让小程序成为正式赛果和积分的唯一依据，同时保留微信群作为自愿的公开交流渠道。正常比赛不要求截图；只有拒绝、确认超时或联赛开启强制截图时才保存证据。管理员只处理异常比赛，不承担逐场截图审核。

成功标准：

- 正常比赛通过“一方提交、对手确认”直接生成官方赛果并更新积分或淘汰赛晋级。
- 对手拒绝或提交后 24 小时未确认时，可以进入有期限的证据收集和管理员仲裁。
- 联赛可配置所有比赛提交时强制上传截图，默认关闭。
- 图片存放在对象存储，单场最多 3 张，官方赛果确定 90 天后删除。
- 图片删除后，比分版本、参与人、时间、原因和操作事件永久保留。
- 微信群和群机器人不参与正式赛果状态流转。

## 范围与非目标

第一版支持联赛级 `resultEvidenceRequired` 开关，不增加赛事级或阶段级覆盖。后续确有需求时，可让赛事或阶段覆盖联赛默认值。

第一版不包括公开证据画廊、其他参赛者查看截图、自动识别截图比分、微信群截图抓取、机器人审核或二次申诉流程。

## 核心规则

### 正常比赛

1. 一方提交比分。
2. 若联赛未开启强制截图，提交时不要求图片。
3. 若联赛开启强制截图，提交方必须同时上传 1 张截图。
4. 比赛进入待确认状态，并记录 24 小时确认截止时间。
5. 对手确认后，比分成为官方赛果，并立即更新积分或淘汰赛晋级。

### 对手拒绝

1. 对手必须填写拒绝原因。
2. 当前比分版本标记为已拒绝。
3. 系统创建争议，触发原因为 `REJECTED`，进入双方补证状态。
4. 双方从争议创建时起各有 24 小时提交 1 张证据。
5. 双方均提交后可提前进入待管理员仲裁；否则补证截止后自动进入。
6. 一方未提交证据不阻止管理员裁决，系统记录其逾期未提交。

### 长期未确认

1. 提交比分 24 小时后仍未确认或拒绝，比分不会自动生效。
2. 提交方获得“上传截图并申请仲裁”操作。
3. 提交方上传证据并申请后，系统创建触发原因为 `CONFIRMATION_TIMEOUT` 的争议。
4. 对手从争议创建时起有 24 小时补充证据。
5. 补证截止后进入待管理员仲裁；对手未提交不阻止裁决。

超时只产生申请仲裁资格，不自动把比赛送入管理员队列，避免参赛者已经线下解决但仍生成无效工单。

### 管理员仲裁

管理员可以采用原提交比分或录入另一比分。管理员必须填写裁决原因，可以选择上传 1 张证据。比赛取消等赛制级操作继续使用现有赛事管理流程，不混入赛果争议仲裁。

裁决产生新的官方赛果版本；已有官方版本标记为已替代但永久保留。裁决完成后立即重新计算积分，或修正淘汰赛胜者与后续晋级关系。管理员只能处理自己有权限的联赛。

## 状态模型

比赛沿用现有状态并增加一个争议状态：

- `AWAITING_RESULT`：等待首次提交或被拒绝后等待重新提交。
- `PENDING_CONFIRMATION`：已经提交，等待对手确认。
- `DISPUTED`：已经创建赛果争议，补证或等待管理员仲裁；此时不允许重新提交比分。
- `CONFIRMED`：双方确认的官方结果。
- `ADMIN_DECIDED`：管理员录入或仲裁后的官方结果。

新增争议状态：

- `EVIDENCE_COLLECTION`：处于双方补证期。
- `READY_FOR_REVIEW`：双方已提交或补证期已结束，等待管理员。
- `RESOLVED`：管理员已经裁决。
- `CANCELLED`：争议因并发确认、比赛取消等合法原因关闭。

争议触发原因：

- `REJECTED`
- `CONFIRMATION_TIMEOUT`

管理员裁决类型：

- `USE_SUBMITTED_SCORE`
- `REPLACE_SCORE`

确认、拒绝、超时申请仲裁和管理员裁决都必须锁定比赛并校验比赛版本。截止前发生的有效确认优先；确认成功后不能再创建超时争议。

拒绝创建争议或超时申请仲裁成功时，比赛进入 `DISPUTED`；管理员裁决后进入 `ADMIN_DECIDED`。争议因并发确认而取消时，以已经成功写入的官方比赛状态为准。

## 数据模型

### 联赛规则

在联赛或联赛规则中增加：

- `resultEvidenceRequired Boolean @default(false)`

### 比赛确认期限

比赛记录增加：

- `resultConfirmationDeadlineAt DateTime?`

比分提交成功时写入当前时间加 24 小时；确认、拒绝或管理员裁决后清空。

### MatchResultDispute

保存：

- 比赛、触发比分版本和触发原因。
- 当前状态。
- 争议发起人和创建时间。
- 补证截止时间。
- 管理员、裁决类型、最终比分、裁决原因和裁决时间。
- 乐观锁版本。

每场比赛同一时间最多有一个未结束争议。

### MatchResultEvidence

保存：

- 可选争议、比赛和可选比分版本。强制截图模式下的正常提交证据可以不属于争议。
- 上传角色：`SUBMITTER`、`OPPONENT` 或 `ADMIN`。
- 上传用户或管理员。
- 对象存储键，不保存图片二进制和永久公开 URL。
- MIME 类型、字节数、内容校验值。
- 创建时间、到期时间、删除时间和删除状态。

每场最多 3 张有效证据：提交方 1 张、对手 1 张、管理员可选 1 张。同一角色在截止前可替换自己的图片；替换也必须留下事件记录，旧对象进入安全清理队列。

现有 `MatchResultVersion.evidenceMetadata` 不再作为新流程的主要存储；兼容读取历史数据，但新证据写入专用表。

### MatchResultEvent

追加写入、不可修改的赛果事件流水，事件至少包括：

- `RESULT_SUBMITTED`
- `RESULT_CONFIRMED`
- `RESULT_REJECTED`
- `CONFIRMATION_EXPIRED`
- `DISPUTE_OPENED`
- `EVIDENCE_UPLOADED`
- `EVIDENCE_REPLACED`
- `EVIDENCE_DEADLINE_EXPIRED`
- `ADMIN_DECIDED`
- `EVIDENCE_DELETED`

事件保存比赛、争议、比分版本、操作者类型与 ID、发生时间以及必要的结构化元数据。确认人和拒绝人必须明确记录，不能只依靠幂等回执推断。

## 图片上传与访问

1. 小程序向 API 申请临时上传凭证和服务端生成的对象键。
2. API 校验比赛身份、当前状态、上传角色、截止时间和数量限制。
3. 小程序压缩图片后直传对象存储。
4. 上传完成后，小程序调用完成接口；API 校验对象存在、大小、类型和校验值，再创建证据记录与事件。

允许 JPEG、PNG 和 WebP。客户端目标大小为 500–800KB，服务端硬限制为 1MB。超限、格式不符或不属于本场比赛的上传不得登记为证据。

上传成功但未完成登记的对象视为临时孤儿，24 小时后清理。查看证据时由 API 签发短时有效地址；证据不使用永久公开 URL。

只有本场双方和具备该联赛权限的管理员可以查看证据。补证期间双方只能看到对方是否已提交，不能查看对方图片；进入管理员裁决后仍只向管理员展示全部证据。

## 图片保留与删除

- 未解决争议的图片不进入 90 天倒计时。
- 双方确认或管理员裁决形成官方赛果后，相关图片到期时间为官方结果确定时间加 90 天。
- 每日清理任务删除到期对象；对象删除成功后才写入删除时间并追加 `EVIDENCE_DELETED` 事件。
- 删除失败保持待删除状态并重试，不能提前宣称已删除。
- 对象存储只对尚未完成登记的临时上传前缀配置 2 天兜底生命周期；正式证据由应用清理任务按解决时间删除，避免误删长期未解决争议。

图片删除后继续永久保留证据元数据、比分版本、上传人、确认人、拒绝原因、裁决原因、操作时间和事件流水。

## 小程序体验

“我的比赛”显示：

- 待提交：录入比分；强制截图时同时上传图片。
- 待对手确认：显示 24 小时截止时间。
- 待我确认：确认或拒绝；拒绝前提示双方需要补证。
- 确认已超时：提交方可以上传截图并申请仲裁。
- 双方补证中：显示剩余时间及双方提交状态。
- 待管理员仲裁：双方只读。
- 已裁决：展示官方比分、裁决原因和操作时间线。

现有待办中心增加赛果来源，聚合待确认、确认超时、需要补证、等待仲裁和裁决完成提醒。正常业务操作仍在比赛与争议详情页完成，待办中心只负责提醒和深链。

## 管理后台

增加“赛果争议”工作台：

- 默认将补证期已结束的争议排在最前。
- 查看比赛、提交比分、拒绝原因、双方证据状态、证据图片和完整事件时间线。
- 录入裁决类型和最终比分。
- 必填裁决原因，可选上传管理员证据。
- 裁决后显示积分或淘汰赛晋级更新结果。

现有管理员直接录入或修改官方比分能力保留。修改已有官方比分仍必须填写原因，并允许可选上传管理员证据。

## 权限与并发

- 只有本场双方可以提交、确认、拒绝和上传各自证据。
- 提交者不能确认或拒绝自己的比分。
- 双方不能删除已经登记的证据，只能在截止前替换自己的证据。
- 管理员只能处理被授权联赛。
- 所有状态变更使用数据库事务、比赛行锁和乐观版本校验。
- 确认、拒绝、超时仲裁并发时只能有一个成功，其余返回版本冲突并刷新页面。
- 已归档球队、已取消赛事和不可见联赛不得继续提交或补证。

## 故障处理

- 图片上传中断：不创建证据记录，不占用证据名额。
- 直传成功但登记失败：对象进入 24 小时孤儿清理。
- 一方逾期未补证：记录逾期，争议照常进入管理员队列。
- 清理失败：保留对象和待删除状态，后台重试。
- 管理员裁决失败：事务回滚，不产生部分官方比分、积分或晋级结果。
- 图片已删除：时间线显示上传元数据和删除时间，不再生成访问地址。

## 测试与验收

- 状态机覆盖正常确认、拒绝争议、确认超时和管理员裁决。
- 验证 24 小时确认期限和 24 小时补证期限的边界时刻。
- 验证截止前确认优先，以及确认、拒绝、仲裁申请的并发冲突。
- 验证强制截图默认关闭，开启后提交方必须上传，对手确认无需重复上传。
- 验证每场 3 张、每角色 1 张、1MB 上限和允许的图片类型。
- 验证临时凭证权限、私有访问和跨比赛越权拒绝。
- 验证孤儿清理、90 天删除、删除重试和删除后结构化记录保留。
- 验证管理员裁决和后续修正必须填写原因。
- 验证管理员裁决后联赛积分、杯赛晋级和历史快照正确更新。
- 验证小程序各状态页面、待办深链和管理后台争议队列。
- 验证提交、确认、拒绝、证据、超时、裁决和删除事件完整可追溯。

## 发布策略

数据库迁移先以默认关闭的联赛开关上线。发布 API 和后台后，再发布小程序页面；旧客户端仍可完成正常无截图确认流程。新争议能力稳定后才允许管理员打开强制截图开关。

监控争议创建量、证据上传失败率、平均仲裁时间、对象存储容量、孤儿清理失败和到期删除失败。强制截图开关的变化必须写入管理员审计日志。

确认期限和补证期限由每 5 分钟运行的状态推进任务处理；接口读取或写入争议时也会校正已经到期但任务尚未处理的状态。证据到期删除任务每日运行。
