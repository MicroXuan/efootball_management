# 赛季日程、球员提名、球队资产与交易操作设计

日期：2026-10-19

## 目标与边界

让参赛者在小程序中看清自己的比赛和赛季关键时期，浏览本联赛其他球队的公开阵容，并从球员档案完成提名、协商转会或强报；管理员可据提名名单组织现有球员拍卖，审核消失申请和双方同意的转会。延续现有拍卖、球员市场、工资规则及球队归属数据，不另建平行账本。截图仅作信息层级与操作参考，不复制其视觉或隐藏的业务规则。

已确认的规则：提名仅限本联赛无归属球员；强报金额是本次愿意出的价格，不修改官方身价；转会须双方确认及管理员审核；消失审核通过后，球员仍归原球队，但进入“已消失”档案，不占一线人数和工资；工资帽由后台管理员逐队确认、后续可手动修改，普通用户不可修改。

## 交付边界与顺序

1. 赛程筛选、赛季日程与提名管理；管理员从提名候选名单导入拍卖草稿。
2. 联赛球队目录与只读资产、本人资产视觉层级和工资帽、窗口外下放提示。
3. 消失申请审核、双方转会、强报入口与群文案。

三个交付段共享现有球队、赛季、球员归属和拍卖接口，但各段分别可验证。不会把复制到微信群的文字当成正式交易申请；服务器记录才是事实来源。

## 页面与交互

### 赛程与日程

- 在现有“全部 / 未开始 / 已结束”筛选列加入第四项“我的赛程”。该项显示当前登录账号在所选赛季的比赛；若账号拥有多支参赛球队，允许明确切换，不能依昵称猜测归属。无参赛球队时展示说明和联赛入口。切换赛季、球队或筛选时清除旧分页，避免混排。
- 联赛详情增加“赛季日程”入口。移动端以月份和日期列表组织比赛、转会窗口、身价窗口、提名窗口；每项显示起止、本地时区和“未开始 / 进行中 / 已结束”，比赛可跳转现有赛程。日程来自已发布的比赛和真实窗口配置，不维护第二份手工时间表。
- 管理员创建、编辑提名窗口（赛季、开始、截止、每队正整数上限）。转会期和身价期读取现有窗口；日程展示不替代其原有管理页或开放条件。

### 提名到拍卖

- 参赛球队在开放的提名窗口内搜索本联赛无归属球员并提名；本队在窗口内可撤回。每队、每窗口、每球员仅有一条有效提名，重复提交得到已有结果；不同球队可提名同一球员。达到上限时明确提示剩余额度为零。
- 提名仅记录意向，不预占球员、不改变归属、不保证上拍。候选列表按球员合并，管理员可展开查看提名球队、时间和人数；非管理员只看自己的提名与公开候选统计，不暴露其他用户的私人信息。
- 管理员选候选球员导入现有拍卖草稿，再选择球员卡、起拍价、最低加价和顺序。导入不自动准备或开拍。导入时及拍卖准备时重新检查球员仍无归属；已被签下的候选项显示不可导入原因。管理员可跳过、调整或移除，不默默替换球员。

### 球队资产

- 联赛球队目录提供队徽、编号、球队名、负责人联赛称呼和阵容人数，点击进入该队资产。本人资产可操作；其他球队资产为独立只读投影，不复用队主专属接口权限。只读投影展示公开的队徽、阵容、现役人数、总工资 / 工资帽、球员身价和卡片信息；不返回私密账号字段或修改用版本令牌。
- 资产页顶部采用紧凑的队徽与身份区，队徽加大并保持原图比例；“总工资 / 工资帽”和一线人数排在球员总身价、队壳价值之前。工资帽读取该球队由管理员设置的金额，不再读取联赛统一帽；未设置时显示“待管理员设置”，不显示虚构的 0。超帽时明确标记，不仅靠颜色区分。
- 后台球队创建表单必须填写正整数工资帽；球队设置页可由有权限的管理员查看、确认或手动修改，并显示修改前后对合规状态的影响。小程序用户只能查看。修改留存管理员、时间、旧值、新值和原因；降低工资帽导致超帽时标记球队超帽，阻止新的增员，但不自动下放或删除球员。
- 本队的“一线 / 已消失 / 已退役”档案沿用现有状态。下放仅在允许卖出的转会窗口可执行：窗口外仍显示禁用入口和原因；有下一窗口时显示开放日期。前端提示不代替服务端再次核验。别队资产不显示下放或消失操作。

### 消失、转会与强报

- 本队现役球员提供“申请标记消失”，填写原因后进入待审核。待审核期间球员仍为现役、继续计入人数和工资；管理员通过后将现有归属状态改为 `DISAPPEARED`，仍保留原球队归属和历史。驳回不修改球员。状态在球员卡与行动中心可追踪；管理员现有恢复现役能力不被自动调用。并发申请和归属变更用版本校验阻止重复处理。
- 协商转会可由卖方或买方发起，明确球员、双方球队及价格。对方确认后进入管理员待审核；对方拒绝、发起方撤回或窗口结束则关闭申请。对方确认后价格与目标不可静默修改，需重新发起。管理员执行前在事务内重验转会窗口、球员归属、目标球队名额和工资帽；不合格时显示具体原因，不进行半笔转会。审核通过时复用现有管理员转会事务，由它完成归属变更、手续费、双方资金流水和交易审计。
- 别队现役球员可进入“协商转会”或现有“发起强报”；按钮仅在资格满足时可用，不符合条件时说明原因。强报价格字段统一称“强报报价”，官方身价仍由身价期管理。正式强报申请提交成功后生成可复制文本，包含申请编号、双方球队编号/名称/负责人、球员中英文名（有数据时）和强报报价；例如“强报｜4号 巴塞罗那（小新）→ 3号 阿贾克斯（嗷呜凶一个）｜Raphael Varane（拉斐尔·瓦拉内）｜强报报价 15000｜申请编号 …”。复制后由用户粘贴到微信群，小程序不声称已代用户发送群消息。

## 数据、权限与状态边界

- 新增赛季提名窗口与提名记录，保存提交球队、球员、状态、时间及版本；数据库约束防重复。管理员候选聚合和球队个人列表分别授权。时间有效性统一按服务器时间判断。
- 在球队数据上保存工资帽及管理员确认状态；新建球队必须提交正整数，存量迁移允许暂时为空。迁移已有球队时，用其联赛当前有效的旧统一工资帽预填并标记“待确认”；在管理员逐队确认前，该预填金额继续作为实际校验值，避免现有交易突然中断。管理员确认时可直接接受或改填，确认后可继续手动修改。若旧联赛从未设置工资帽，球队保持“待设置”，管理员补填前禁止会新增球员或提高工资的操作。原工资档位继续决定球员工资，后台工资档位页不再提供联赛统一工资帽编辑；旧统一帽只保留历史记录与迁移来源。签约、转会、强报、状态重算和页面展示统一读取球队工资帽。
- 新增消失申请和协商转会申请及审计事件；管理员审核需具备联赛管理权限，球队确认只能由对应球队负责人执行。所有会改变归属、工资或资金的步骤使用事务、幂等键与乐观版本；拒绝、失效和撤回保留历史。
- 只读资产接口必须验证联赛可见范围，仅返回公开字段。本队写操作继续走队主授权，不因开放浏览而放宽。
- 窗口截止与提交竞态、重复提名、球员在候选期被签下、确认时换队、工资帽更新、管理员并发审核，都由后端返回确定状态和可恢复提示；页面刷新后展示服务器事实。

## 验证与非目标

为时间边界、身份授权、重复/跨队提名、候选导入、审核状态、转会竞争条件、逐队工资帽迁移/确认/修改及工资帽重验写服务和契约测试；为第四筛选项、空状态、只读/可操作资产、禁用下放、申请与复制文案写小程序测试。检查现有拍卖和强报回归，运行类型检查与相关构建，并在微信开发者工具中检查移动端布局。

本轮不实现自动向微信群发文本、不把提名自动变成拍卖、不把强报报价自动改为官方身价、不自动划拨与本次需求无关的历史财务。实际生产联调需使用有效微信环境、完整赛季窗口配置及测试球队。
