# 自动加点总评工资设计

**日期：** 2026-10-07
**状态：** 已确认
**范围：** 工资档位、阵容工资快照、买入与转会校验、卡片升级、推荐卡排序和管理端展示

## 1. 背景

当前联赛阵容系统使用 PESDATA 的 `dtRating` 匹配工资档位，并在球员加入阵容时保存 `dtRatingSnapshot`。这一实现与最新产品口径不符：球员工资的主要计算依据应当是具体球员卡的“自动加点总评”，即自动加点结果中的 `maxOverall`。

PESDATA 的 `dtRating` 是可空的上游字段，并非每张球员卡都保证提供。`maxOverall` 则属于完整自动加点结果的必填字段。因此 DT 不应决定球员能否加入阵容，也不应继续作为工资、工资帽或推荐卡的核心业务输入。

本设计取代《联赛球队与赛事管理后台设计》中以 DT 计算工资、保存 DT 工资快照以及以 DT 作为推荐卡次级排序条件的相关规则。其他球队、阵容、工资帽、交易和审计规则保持不变。

## 2. 目标

- 使用自动加点总评匹配联赛工资档位。
- 买入、球队间转会、卡片升级和工资重算采用同一套总评定薪逻辑。
- 缺少 DT 不影响球员卡进入阵容；缺少完整自动加点结果仍禁止操作。
- 阵容保存自动加点总评、工资规则版本和工资结果快照。
- 管理端只展示对业务决策有用的自动加点总评，不在阵容操作中展示 DT。
- 保留 PESDATA 原始 DT 数据，避免破坏导入兼容性和数据追溯能力。
- 已有阵容迁移后保持原工资不变，由管理员明确发起重新核算。

## 3. 非目标

- 不在本次改动中推导或重新计算 PESDATA 的 DT。
- 不删除球员自动加点记录中的原始 `dtRating`。
- 不修改自动加点算法、能力点分配或 `maxOverall` 的生成方式。
- 不自动改写历史交易中的旧工资、新工资和操作结果。
- 不引入按位置、卡片类型或球员属性加权的新定薪公式。

## 4. 领域规则

### 4.1 工资依据

每张可加入阵容的球员卡必须存在完整自动加点结果：

- `allocationJson`
- `maxOverall`
- `algorithmVersion`

工资服务使用 `maxOverall` 查找当前生效工资规则中唯一覆盖该数值的档位。工资档位必须连续、无重叠，并覆盖系统支持的总评范围 `0–120`。

默认工资金额保持不变，只把档位含义从 DT 改为自动加点总评：

| 自动加点总评 | 默认工资 |
|---:|---:|
| 92 及以下 | 100 |
| 93 | 200 |
| 94 | 300 |
| 95 | 400 |
| 96 | 500 |
| 97 | 600 |
| 98 | 700 |
| 99 | 800 |
| 100 及以上 | 900 |

每个联赛仍可发布自己的工资规则版本并调整档位金额。

### 4.2 阵容快照

球员加入阵容或完成卡片升级时，系统保存：

- 当前球员卡 ID；
- `maxOverallSnapshot`；
- 工资规则版本 ID；
- 工资结果 `salaryMinor`。

此后上游重新同步、自动加点算法升级或推荐卡变化，都不得静默改变已持有球员的总评快照和工资。

### 4.3 交易校验

买入、球队间转会和卡片升级统一执行以下顺序：

1. 读取所选球员卡最新的完整自动加点结果；
2. 使用 `maxOverall` 获取当前工资报价；
3. 计算操作后的球队工资；
4. 校验工资帽；
5. 在同一事务中保存总评、工资版本和工资快照。

`dtRating` 为空不再产生业务错误。没有自动加点记录时仍返回 `PLAYER_AUTO_BUILD_MISSING`。由于完整自动加点记录要求 `maxOverall`，不新增“缺少总评”的独立错误码。

### 4.4 工资规则变更

发布新工资规则只影响后续买入、转会和卡片升级，不自动修改已有阵容。

管理员执行现有“重新核算”操作时，系统读取每条有效阵容记录的 `maxOverallSnapshot`，使用指定工资规则版本重新计算工资，并写入不可修改的工资重算交易记录。重新核算不读取当前 PESDATA 数据，避免上游数据更新改变历史持有卡片的定价基础。

### 4.5 推荐卡排序

同一真实球员有多张卡时，推荐卡排序改为：

1. 自动加点总评降序；
2. 卡片发布日期降序，空日期排后；
3. 外部卡片 ID 升序。

DT 不再参与排序。推荐结果的 `selectionReason` 必须同步记录新的排序字段，避免继续生成包含 `dtRating:desc:nulls-last` 的过时解释。

## 5. 数据模型与迁移

### 5.1 保留原始 DT

`PlayerCardAutoBuild.dtRating` 保留为可空字段。PESDATA 同步、JSON/CSV 导入和自动加点记录写入行为不变。该字段仅属于上游原始数据，不再进入阵容核心业务。

### 5.2 工资档位命名

`LeagueSalaryTier` 的字段从：

- `minDtRating`
- `maxDtRating`

改为：

- `minOverall`
- `maxOverall`

数据库列同步重命名为 `min_overall` 和 `max_overall`。现有档位的数值和金额原样保留，只改变业务含义与字段命名。

### 5.3 阵容快照迁移

`LeaguePlayerOwnership` 新增非空 `maxOverallSnapshot`，数据库列名为 `max_overall_snapshot`。

迁移时根据每条阵容记录的 `currentPlayerCardId` 查找该卡片最新的自动加点记录，并使用其 `maxOverall` 回填。若已有阵容引用的卡片没有自动加点记录，迁移必须中止并报告具体 ownership ID，不能以初始总评、DT 或固定默认值代替。

旧 `dtRatingSnapshot` 在第一阶段保留为可空兼容字段，不再被任何新业务读写。待生产数据完成迁移验证后，可在独立清理版本中删除，避免本次迁移不可逆地丢失历史来源信息。

迁移不修改已有 `salaryMinor`、工资规则版本引用或历史交易。

## 6. API 与契约

工资规则请求和响应中的字段统一改为：

- `minOverall`
- `maxOverall`

阵容条目继续返回 `maxOverall`，其值来自 `maxOverallSnapshot`，而不是实时自动加点记录。阵容、购买候选和升级候选不再返回或展示业务用途的 `dtRating`。

工资报价与预览在内部使用 `overall` 参数。对外错误详情需要具体说明缺少自动加点结果、未配置覆盖该总评的工资档位，或操作后超过工资帽，不再出现“缺少 DT”或“DT 档位”文案。

本次改动不提供旧字段和新字段并存的双写兼容期。管理端、API 和共享契约在同一版本发布，避免客户端继续以 DT 名义配置实际总评档位。

## 7. 管理端交互

### 7.1 阵容与候选卡

- 阵容表保留“自动加点总评”，移除“DT”列。
- 购买球员抽屉只展示初始总评、自动加点总评、工资和工资影响。
- 卡片升级抽屉只展示自动加点总评、升级后工资和工资帽影响。
- 缺少 DT 不显示错误，也不禁用确认按钮。
- 缺少自动加点结果时明确显示“缺少自动加点结果，不能加入阵容”。

### 7.2 工资规则

- 页面标题改为“工资帽与自动加点总评档位”。
- 表格列名改为“自动加点总评范围”。
- 校验提示改为“总评档位必须无重叠、无空档并覆盖 0–120”。
- 工资影响预览继续展示球队当前工资、预计工资、差额和预计状态。

所有错误提示必须描述具体失败操作和原因，不使用笼统的“其他后台操作”等占位文案。

## 8. 小程序

小程序阵容条目保留自动加点总评和工资，移除 `DT` 文案。小程序仍为只读，不新增工资规则编辑或阵容操作能力。

## 9. 审计与历史

- 新增或调整工资规则仍记录规则版本、工资帽、档位和操作管理员。
- 买入、转会、升级继续保存当时工资和工资规则版本。
- 工资重算继续生成逐球员交易记录，并保存旧工资、新工资和目标规则版本。
- 历史记录不按当前球员卡数据即时重算。
- 原始 DT 数据保留在自动加点记录及迁移前的兼容快照中，仅用于数据追溯。

## 10. 验收标准

- 一张 `maxOverall = 95`、`dtRating = 91` 的卡按总评 95 的档位定薪。
- 一张 `maxOverall = 95`、`dtRating = null` 的卡可以正常买入、转会和升级。
- 没有自动加点记录的卡不能加入阵容，并返回 `PLAYER_AUTO_BUILD_MISSING`。
- 工资帽校验使用按自动加点总评计算出的工资。
- 阵容保存并返回 `maxOverallSnapshot` 对应的总评，后续上游更新不改变该值。
- 工资重新核算读取阵容总评快照，不读取实时 DT 或实时自动加点结果。
- 推荐卡在总评相同时按发布日期和外部 ID 决胜，DT 差异不改变结果。
- 管理端阵容、购买、升级和工资规则页面不再出现 DT 业务文案。
- 小程序阵容不再出现 DT 文案。
- 数据迁移不会静默修改已有工资或历史交易。

## 11. 验证范围

- 共享契约：总评档位连续性、边界和响应字段。
- 数据迁移：正常回填、缺少自动加点记录时中止、原工资保持不变。
- API 单元测试：报价、预览、买入、转会、升级、重算和推荐排序。
- API 端到端测试：缺少 DT 仍可买入，总评工资和工资帽校验正确。
- 管理端测试：DT 列与提示消失，总评、工资和操作禁用状态正确。
- 小程序视图模型测试：只展示自动加点总评和工资。
- 全仓类型检查、单元测试、端到端测试和构建。
