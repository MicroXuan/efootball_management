# 非概念实况 UI 风格迭代设计

日期：2026-10-01

## 1. 目标

本次迭代统一微信原生小程序与 React/Ant Design 管理后台的视觉语言，在不修改业务流程、API 或数据库结构的前提下，将参考设计中的暗色足球氛围、荧光绿强调、圆角组件和清晰数据层级应用到现有产品。

最终效果应满足：

- 小程序采用全暗色、沉浸式足球视觉。
- 管理后台采用深色导航框架与浅色数据工作区。
- 所有固定界面文案使用中文；业务专有缩写必须搭配中文含义。
- 矩形容器尽量改为圆角矩形，仅分隔线、球场线和表格行边界保留直线。
- 不引入在线字体、新 UI 框架、动画库或大型装饰图片。
- 现有业务行为、权限、数据加载和表单提交逻辑保持不变。

## 2. 设计方向

采用“赛场夜视 × 数据白场”方向。

小程序承载面向参赛者的浏览、比赛和球队体验，应接近夜间球场与直播界面的沉浸感。管理后台承载高密度表格、表单和长时间操作，保留浅色数据区域以保证阅读效率；深色侧边栏、荧光绿状态和统一圆角负责建立与小程序之间的品牌联系。

参考设计中的高成本元素不会原样复制。全屏模糊、持续发光动画、大型装饰图片和复杂玻璃效果被替换为 CSS 渐变、小范围阴影、现有业务图片和短时交互动效。

## 3. 视觉系统

### 3.1 颜色

共享品牌色：

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| 品牌荧光绿 | `#B0FF00` | 主按钮、选中态、关键数据、主要状态 |
| 辅助黄绿 | `#D9E342` | 次级强调、提醒、赛季节点 |
| 危险红 | `#F04455` | 删除、失败、危险状态 |
| 警告橙 | `#F5A524` | 风险、待处理、接近上限 |

小程序：

| 角色 | 色值 |
| --- | --- |
| 页面背景 | `#0A0A0A` |
| 一级卡片 | `#171917` |
| 二级卡片 | `#20231F` |
| 深色边框 | `#30342E` |
| 主文字 | `#F7F8F5` |
| 次级文字 | `#A0A69D` |
| 弱文字 | `#6F766D` |

管理后台：

| 角色 | 色值 |
| --- | --- |
| 侧边栏背景 | `#0A0A0A` |
| 侧边栏卡片 | `#191B19` |
| 工作区背景 | `#F3F5F1` |
| 内容卡片 | `#FFFFFF` |
| 主文字 | `#171A17` |
| 次级文字 | `#626960` |
| 浅色边框 | `#DDE2D9` |

颜色使用原则：

- 荧光绿只强调当前状态和主要操作，不能覆盖所有文字或边框。
- 普通卡片依靠表面明度差区分，不使用大面积绿色填充。
- 错误、警告和危险操作继续使用语义颜色，不能因为品牌统一而全部改绿。
- 文本与背景保持清晰对比，弱文字也必须满足实际阅读需求。

### 3.2 字体与层级

不下载 Roboto 或其他在线字体。字体栈统一为：

```css
-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif
```

数据、编号和比分可使用：

```css
"DIN Alternate", "SFMono-Regular", Consolas, monospace
```

字号层级：

| 层级 | 小程序 | 管理后台 | 字重 |
| --- | --- | --- | --- |
| 页面主标题 | 48–54rpx | 28–32px | 700–800 |
| 模块标题 | 30–34rpx | 18–20px | 700 |
| 卡片标题 | 27–31rpx | 15–17px | 600–700 |
| 正文 | 24–28rpx | 14px | 400–500 |
| 辅助信息 | 20–23rpx | 12–13px | 400–500 |
| 关键数字 | 32–48rpx | 22–32px | 700–800 |

现有楷体标题全部改为系统无衬线字体。层级主要通过字号、字重、颜色和间距建立，不依赖过度字距。

### 3.3 中文文案

- 导航、页面标题、栏目眉题、状态、按钮、错误提示和空状态全部使用中文。
- 删除 `SCOUTING INDEX`、`LEAGUE WORKSPACE`、`OPERATIONS` 等纯装饰英文。
- `DT 总评` 等业务专有名词可保留缩写，但必须搭配中文含义。
- 球员英文名、卡片原始名称、外部数据和版本号不强制翻译。
- 操作使用明确动词，例如“保存修改”“创建联赛”“确认转会”，避免含糊的“提交”。

### 3.4 圆角、边框与阴影

| 元素 | 小程序 | 管理后台 |
| --- | --- | --- |
| 大型内容卡片 | 28–32rpx | 16–18px |
| 普通卡片 | 20–24rpx | 12–16px |
| 输入框与按钮 | 16–22rpx | 10–12px |
| 胶囊标签 | 高度的一半 | 高度的一半 |
| 弹窗 | 28rpx | 18px |

- 卡片使用细边框和表面明度差，不使用重阴影堆叠。
- 小程序关键状态允许小范围绿色辉光；普通卡片不得发光。
- 后台卡片使用低对比柔和阴影，表格行主要依靠分隔线。
- 抽屉左上角和左下角使用大圆角。
- 只有球场线、时间线、表格行和内容分隔线保留直线视觉。

### 3.5 间距

- 小程序页面左右安全边距统一为 28–32rpx。
- 小程序页面主模块间距为 40–48rpx，卡片内部间距为 24–30rpx。
- 管理后台内容区最大宽度约 1440px，页面边距为 28–36px。
- 后台卡片间距为 20–24px；高密度表格保持紧凑行高。
- 窄屏后台切换为单栏，不压缩双栏表单到不可读宽度。

## 4. 标志性组件：赛场数据胶囊

“赛场数据胶囊”是两端共享的品牌组件，用于承载比分、赛季状态、工资、DT 总评、阵容人数、报名状态和交易状态。

组件规则：

- 圆角胶囊外形。
- 默认使用中性表面和次级文字。
- 进行中、当前值或主要状态使用荧光绿。
- 警告和危险状态使用语义色。
- 同一模块内最多只有一个高亮胶囊，避免失去视觉优先级。
- 数字使用等宽或窄体字体，中文说明使用系统无衬线字体。

## 5. 小程序布局

### 5.1 列表页模板

适用页面：球员、联赛、赛事、我的比赛、我的球队。

结构：

1. 圆角页面标题区。
2. 搜索框和横向筛选胶囊。
3. 必要时显示关键状态概览。
4. 圆角内容卡片列表或卡片网格。
5. 悬浮圆角底部导航。

球员卡保留三列结构，但统一圆角、暗色层次、评分角标和文字截断规则。联赛、赛事和比赛采用横向信息卡，将状态、时间、名额和比分放进数据胶囊。

### 5.2 详情页模板

适用页面：球员卡详情、联赛详情、球队详情、赛事详情。

结构：

1. 圆角沉浸式头图或品牌区。
2. 关键数据胶囊横排区域。
3. 当前状态主卡片。
4. 分组信息卡片。
5. 底部主要操作区。

有业务图片时使用球员、联赛或球队图片；没有图片时使用 CSS 径向渐变和轻量球场纹理，不添加装饰图片下载。

### 5.3 表单与操作页模板

适用页面：比赛结果、赛事管理、赛事编辑、账号编辑、球队资料编辑、赛季管理。

结构：

1. 标题和圆角返回按钮。
2. 当前步骤或状态提示。
3. 分组圆角表单卡。
4. 吸底圆角操作栏。

危险或不可逆操作必须与主要操作分区，不能只依赖颜色区分。

### 5.4 底部导航

使用原生小程序自定义 TabBar，不引入第三方组件。

- 外层为悬浮深色圆角容器。
- 选中项使用荧光绿色胶囊和深色图标。
- 未选中项使用弱文字和线性图标。
- 保留球员、联赛、我的三项现有信息架构。
- 适配底部安全区和较小屏幕。

## 6. 管理后台布局

### 6.1 全局框架

- 固定深色侧边栏，包含圆角品牌标识、圆角导航项和联赛入口。
- 顶部使用浅色圆角状态栏，显示当前工作区、管理员身份和退出操作。
- 主区域使用浅灰背景与白色圆角数据卡片。
- 导航选中态使用荧光绿，但侧边栏不出现大面积绿色背景。

### 6.2 页面模板

列表和创建表单继续采用左右双栏：

- 左侧为主要数据列表。
- 右侧为创建或编辑表单。
- 宽度低于 1100px 时切换为单栏。

详情和工作区页面：

- 顶部展示联赛或球队上下文。
- 标签导航改为圆角分段控件。
- 内容使用独立白色卡片承载。
- 关键数字和状态使用赛场数据胶囊。

表格：

- 保持高信息密度。
- 表头使用轻灰底色和较强字重。
- 行悬停只使用轻微绿色背景。
- 操作按钮使用圆角文字按钮或紧凑胶囊按钮。
- 横向溢出时允许滚动，不能压缩列到不可读。

### 6.3 弹窗与抽屉

- 弹窗使用 18px 圆角和清晰的标题、内容、操作分区。
- 抽屉采用浅色内容面板，左侧两个角使用大圆角。
- 表单控件高度和圆角保持一致。
- 主要操作固定在可见位置，错误提示紧邻相关表单区域。

### 6.4 登录页

- 左侧保留足球品牌区，改为黑色和荧光绿体系。
- 右侧使用浅色圆角登录卡片。
- 删除楷体和英文栏目眉题，所有说明使用中文。
- 球场图形继续使用 CSS 绘制，不使用大型背景图。

## 7. 代码组织

### 7.1 小程序

- 在 `apps/miniprogram/miniprogram/app.wxss` 定义全局设计变量和通用基础类。
- 页面 WXSS 只保留页面专属布局，逐步移除重复颜色值和重复状态卡样式。
- 提取页面标题、数据胶囊、状态卡和自定义底部导航等公共组件。
- 组件内部保留必要样式，并继承共享设计变量。
- 不改变 ViewModel、请求服务和页面事件的数据契约，除非结构调整需要增加纯展示字段。

### 7.2 管理后台

- 在 `ConfigProvider` 中统一 Ant Design 的颜色、圆角、控件高度和组件 Token。
- 在 `apps/admin-web/src/styles.css` 中维护全局布局、品牌表面和响应式规则。
- 为页面增加少量语义类名，避免使用高优先级选择器覆盖组件。
- 保留 React 页面懒加载和现有 API 请求逻辑。
- 不新增 UI 依赖。

## 8. 性能与动效

- 不增加在线字体、动画库、UI 框架或大型装饰图片。
- 不使用高成本全屏 `backdrop-filter` 和持续循环动画。
- 辉光通过小范围 `box-shadow` 和 `radial-gradient` 实现。
- 业务图片启用懒加载，设置固定容器比例，减少布局跳动。
- 交互动效控制在 150–220ms，仅使用颜色、透明度和小范围位移。
- 遵循 `prefers-reduced-motion`；小程序提供无持续动画的默认体验。
- 自定义 TabBar 使用原生组件和本地轻量图标。

## 9. 可访问性与状态设计

- 主文字、次级文字和禁用文字均保持可辨识对比度。
- 桌面端保留清晰的键盘焦点轮廓。
- 小程序主要触控区域不小于推荐触控尺寸。
- 禁用态同时使用透明度、文字和交互状态表达，不只改变颜色。
- 错误信息说明发生了什么以及用户下一步可以做什么。
- 空状态给出明确下一步，不使用纯装饰性文案。
- 加载、空、失败、无权限和版本冲突状态都必须适配新视觉系统。

## 10. 实施范围

小程序覆盖：

- 登录与个人中心。
- 球员列表与球员卡详情。
- 联赛列表、联赛详情、我的球队与球队详情。
- 赛事列表、赛事详情、我的比赛与比赛结果。
- 现有赛事、赛季、球队资料和游戏账号编辑管理页。
- 公共加载状态、球员卡和底部导航。

管理后台覆盖：

- 登录页和全局应用框架。
- 平台联赛、管理员账号和审计日志。
- 联赛工作区、球队、赛季、工资规则和转会窗口。
- 阵容、球员获取、转会、卡片升级和财务流水。
- 所有弹窗、抽屉、表单、表格、错误和空状态。

本次明确不包含：

- API、数据库或权限模型修改。
- 新业务功能。
- 新图片素材生产。
- 远程字体或第三方动效资源。
- 为视觉效果引入新的运行时依赖。

## 11. 测试与验收

自动验证：

- 更新受中文文案、DOM 结构和公共组件调整影响的现有测试。
- 运行管理后台单测、类型检查和生产构建。
- 运行小程序 ViewModel 测试、类型检查和构建检查。
- 完成后运行仓库完整验证命令。

视觉验证：

- 小程序检查常见手机宽度、长内容、空状态和底部安全区。
- 后台检查桌面宽屏、约 1100px 临界宽度和窄屏单栏。
- 选择登录页、列表页、详情页、表单页和后台数据页进行截图复核。
- 检查颜色、字号、圆角、间距、溢出、焦点、禁用态和交互动效。

验收标准：

- 两端能被识别为同一产品，但符合各自使用场景。
- 小程序保持全暗色沉浸体验，后台数据区保持浅色高可读性。
- 固定界面文案全部中文化。
- 可见矩形容器优先使用圆角矩形。
- 页面主要操作和关键状态在三秒内可识别。
- 不出现新的大型依赖、字体请求或无必要图片请求。
- 现有业务测试和构建全部通过。
