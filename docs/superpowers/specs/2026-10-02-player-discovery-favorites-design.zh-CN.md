# 球员发现与收藏设计

## 背景与目标

本设计落实《实况足球需求路线图》的 R3、R11，并补齐 R12 中与现有管理流程直接相关的筛选能力。目标是让小程序用户可以通过位置、卡种和球员包快速找到球员，收藏喜欢的球员，并始终看到该球员当前最值得展示的卡片；同时让联赛管理员在现有球队和阵容工作流中更快筛选球队与候选球员。

本批次不新增独立后台球员资料库、不改变球员同步来源，也不扩展为社交收藏、收藏夹分类或收藏排序系统。

## 产品规则

### 收藏对象

- 收藏对象是足球球员，而不是某一张具体卡片。
- 同一用户只能收藏同一球员一次。
- 收藏列表默认展示 `FootballPlayerBestCard` 选出的自动加点最高能力卡。
- 若球员尚无 `FootballPlayerBestCard`，回退到该球员当前有效卡片中基础总评最高的卡；总评相同时按发布时间较新、卡片 ID 稳定排序。
- 球员没有任何有效卡片时不出现在收藏列表中，但收藏关系保留，以便后续同步恢复。

### 小程序体验

- 球员档案页保留现有关键词、位置、卡种筛选，并增加球员包下拉选择。
- 球员列表和球员卡详情展示收藏状态，登录用户可以收藏或取消收藏。
- 新增“我的收藏”页面，复用球员卡片浏览样式，支持关键词搜索。
- 收藏页面按最近收藏时间倒序排列；列表返回球员及其当前推荐卡，而不是所有卡片。
- 收藏请求失败时保留当前界面状态并显示中文错误，不做虚假的乐观成功。

### 后台筛选

- 购买球员抽屉在现有关键词搜索上增加位置、卡种和球员包筛选。
- 球队管理页增加本地即时筛选，可按球队名称、简称、球队编号或负责人名称匹配。
- 继续使用现有页面和接口边界，不新增重复的后台导航栏目。

## 数据模型

新增 `UserPlayerFavorite`：

- `id`
- `userId`
- `footballPlayerId`
- `createdAt`
- `updatedAt`

约束与关系：

- `@@unique([userId, footballPlayerId])` 防止重复收藏。
- 用户或球员删除时级联删除收藏关系。
- 为 `userId, createdAt` 建立列表索引，为球员反查建立 `footballPlayerId` 索引。

不在收藏表冗余卡片 ID。推荐卡由查询时根据现有最佳卡选择结果解析，避免球员同步或自动加点重算后出现过期收藏卡。

## 接口与契约

新增登录用户接口：

- `GET /v1/me/player-favorites?keyword=&cursor=&limit=`：返回收藏列表和下一页游标。
- `POST /v1/me/player-favorites`，请求体 `{ playerId }`：幂等收藏。
- `DELETE /v1/me/player-favorites/:playerId`：幂等取消收藏。
- `GET /v1/me/player-favorites/status?playerIds=`：批量返回列表页所需的收藏状态，限制查询数量。

响应中的收藏条目包含 `playerId`、收藏时间和推荐 `PlayerCardSummary`。所有 ID、分页大小和关键词继续使用 Zod 契约校验。

现有球员搜索接口已经支持 `cardPackId`，小程序补齐传参即可。后台候选球员接口扩展位置、卡种和球员包参数，并在服务层复用对应筛选语义。

## 服务边界与数据流

`PlayerFavoritesService` 只负责用户收藏关系和推荐卡解析：

1. 写入时验证球员存在，使用唯一键 upsert。
2. 列表先读取当前用户收藏关系，再批量加载球员、最佳卡与当前发布版本。
3. 推荐卡优先使用 `FootballPlayerBestCard`；不可用时从当前有效版本中确定回退卡。
4. 关键词匹配中文名、英文名、简称和推荐卡名称。
5. 分页游标由收藏时间和收藏 ID 组成，保证同时间记录稳定翻页。

`PlayerCatalogService` 继续负责公共球员目录；收藏服务不复制目录搜索实现，也不改变现有目录快照行为。

## 权限与错误处理

- 收藏接口必须登录，只允许读写当前用户自己的收藏。
- 不接受客户端传入 `userId`。
- 收藏不存在的球员返回中文可映射的 `PLAYER_NOT_FOUND`。
- 重复收藏和重复取消都返回成功语义，方便小程序安全重试。
- 批量状态查询设置数量上限，避免超长 URL 和无界数据库查询。
- 球员包加载失败不阻断球员列表，页面保留“全部球员包”并提示可重试。

## 性能与兼容性

- 不增加图片处理或前端大型依赖。
- 收藏列表采用批量查询，禁止逐条查询卡片造成 N+1。
- 小程序继续每页加载 20 条；球员包选择只保存 ID 和短标签。
- 现有球员搜索和卡片详情响应保持兼容，新字段只以可选形式扩展。
- 数据库变更通过独立 Prisma migration 交付。

## 测试与验收

### API

- 首次收藏、重复收藏、取消收藏、重复取消均符合幂等语义。
- 用户之间收藏隔离。
- 推荐卡优先使用自动加点最佳卡，并覆盖无最佳卡时的回退排序。
- 无有效卡的收藏不进入列表但关系仍存在。
- 关键词、分页和批量状态上限正确。
- 后台候选球员组合筛选正确。

### 小程序

- 球员包加载、选择、清空后生成正确查询。
- 收藏按钮根据批量状态展示，并在成功后更新。
- 收藏页搜索、分页、空态和错误态正确。
- 卡片详情收藏的是球员 ID，而不是卡片 ID。

### 管理后台

- 购买球员抽屉将位置、卡种和球员包参数发送到接口。
- 球队列表可按名称、简称、编号和负责人筛选。
- 筛选无结果时显示明确空态，不影响创建球队表单。

- 新增和受影响测试全部通过。
- 全仓 lint、类型检查、单元测试、端到端测试和构建均通过；若存在与本批次无关的历史失败，必须明确列出。
