# 微信群多功能绑定与拍卖群隔离设计

日期：2026-10-10
状态：待用户审阅

## 1. 背景与目标

当前系统已经支持微信群绑定联赛、赛程查询和球员拍卖，但群绑定没有显式的功能边界。拍卖命令会先于赛程命令进入拍卖处理器，因此同一联赛使用多个不同用途的微信群时，无法由管理员明确声明哪些群用于赛程查询、哪些群用于球员拍卖。

本次改造的目标是：

- 一个微信群仍然只能绑定一个联赛；
- 一个联赛可以绑定多个微信群；
- 每个群可以独立启用赛程查询、球员拍卖，或同时启用两者；
- 查询、拍卖和倒计时消息严格留在对应群内；
- 拍卖批次由管理员在后台选择目标拍卖群；
- 不强制限制同一联赛的多个拍卖群是否同时开拍，由管理员自行安排；
- 保留现有群 ID、设备、赛程来源、身份绑定和拍卖数据。

## 2. 已确认的业务规则

### 2.1 群与联赛

- 一个群绑定一个联赛，不支持跨联赛复用同一个微信群。
- 一个联赛可绑定任意多个已被机器人观察到的微信群。
- 每个群有独立的总开关和功能集合。
- 群名仅用于显示和发送前核验，稳定微信群 ID 才是路由主键。

### 2.2 群功能

首期提供两个功能：

- `SCHEDULE_QUERY`：赛程查询；
- `PLAYER_AUCTION`：球员拍卖。

一个群可以拥有零个、一个或两个功能。功能组合示例：

| 群 | SCHEDULE_QUERY | PLAYER_AUCTION | 行为 |
| --- | --- | --- | --- |
| 查询群 | 是 | 否 | 只处理赛程命令 |
| 拍卖群 | 否 | 是 | 只处理拍卖命令和数字出价 |
| 综合群 | 是 | 是 | 两类命令都处理 |
| 暂停用途群 | 否 | 否 | 不处理群命令 |

### 2.3 命令隔离

- `查询赛程`、`我的赛程`只在启用 `SCHEDULE_QUERY` 的群中处理。
- `开始拍卖`、`暂停拍卖`、`继续拍卖`、`下一位`、`取消拍卖`和纯数字出价只在启用 `PLAYER_AUCTION` 的群中处理。
- 未启用拍卖功能的群收到纯数字时静默忽略，避免普通聊天数字触发机器人。
- 未启用查询功能的群收到赛程命令时静默忽略。
- `帮助`根据当前群的功能集合动态生成，只展示该群可用命令。
- 私聊身份绑定不属于群功能，继续按设备和微信联系人处理。

## 3. 数据模型

新增群功能枚举和关联模型，而不是继续向群绑定表增加布尔字段：

```text
WechatGroupCapabilityType
  SCHEDULE_QUERY
  PLAYER_AUCTION

WechatGroupCapability
  id
  groupBindingId
  capability
  createdByAdminId
  createdAt
```

约束与索引：

- `(groupBindingId, capability)` 唯一；
- 按 `capability` 建索引，支持筛选可用于拍卖的群；
- `groupBindingId` 和 `createdByAdminId` 都采用 `onDelete: Restrict`，与现有群赛程来源和拍卖批次的审计规则一致；
- `AdminAccount` 增加对应的功能创建记录反向关系；
- `WechatGroupBinding` 增加 `capabilities` 关系，不改变现有唯一约束：同一设备和稳定群 ID 仍只能有一个绑定。

API 中统一使用：

```json
{
  "capabilities": ["SCHEDULE_QUERY", "PLAYER_AUCTION"]
}
```

## 4. 后台配置

### 4.1 微信群机器人页面

同一联赛可逐个保存多个群绑定。每个群显示：

- 最新群名与稳定群 ID；
- 所属机器人设备和在线状态；
- 群总开关；
- “赛程查询”复选框；
- “球员拍卖”复选框；
- 该群的赛程来源。

界面行为：

- 勾选“赛程查询”时展示赛程来源选择；
- 取消“赛程查询”或关闭群总开关时保留已选赛程来源，以便重新启用；
- 取消“球员拍卖”时不删除历史拍卖数据；
- 群总开关关闭时所有群命令停止处理，但功能和来源配置保留；
- 群名变化时更新显示名，不改变绑定和功能。

### 4.2 拍卖批次页面

- 创建拍卖批次时，只展示当前联赛下同时满足 `enabled = true` 和 `PLAYER_AUCTION` 的群。
- 批次保存后继续固定使用所选 `groupBindingId`。
- 所有开拍、出价确认、倒计时、结束、恢复和完成消息只发往该绑定群。
- 系统不限制同一联赛的多个拍卖群是否同时开拍。

### 4.3 活跃拍卖保护

当群仍被 `READY`、`ACTIVE`、`PAUSED` 或 `RECOVERY_REQUIRED` 的拍卖批次引用时：

- 不允许关闭群总开关；
- 不允许移除 `PLAYER_AUCTION`；
- 后台返回可识别的冲突代码和中文提示，要求管理员先完成或取消相关批次。

该保护只防止拍卖失联，不限制管理员为同一联赛配置或运行多个拍卖群。

## 5. 命令路由与权限

入站消息仍先通过设备、稳定群 ID 和启用状态定位 `WechatGroupBinding`。命令路由在调用具体处理器前加载功能集合：

1. 未绑定或已停用的群按现有规则忽略；
2. 数字和拍卖管理指令只有在包含 `PLAYER_AUCTION` 时才进入拍卖处理器；
3. 赛程命令只有在包含 `SCHEDULE_QUERY` 时才进入赛程服务；
4. `帮助`由启用功能动态组合；
5. 不满足功能条件的命令以明确的内部结果码静默结束，不创建 outbox。

权限规则保持不变：

- 拍卖管理员必须先完成微信身份绑定；
- 管理指令必须通过 `league.auction.manage` 联赛权限校验；
- 出价者必须绑定身份，并拥有当前联赛的有效球队；
- 群功能不能绕过身份、球队、价格、时序或拍卖状态校验。

## 6. 拍卖流程

### 6.1 准备与开拍

管理员在后台创建批次，选择已启用拍卖功能的群，添加球员、显示顺序、起拍价和最低加价，并将批次准备完成。具有权限的管理员在目标群发送 `开始拍卖` 后：

1. 机器人发送待拍球员列表；
2. 发送第一位球员信息；
3. 价格统一使用星号格式，例如 `起拍价：⭐50⭐`；
4. 开拍消息说明 30 秒出价时间，不单独发送 `30`。

### 6.2 出价

- 群成员只发送纯数字，例如 `120`。
- 系统按微信发送时间、排序键、消息 ID 和数据库 ID形成稳定顺序。
- 系统校验身份、球队、联赛、批次、当前球员、截止时间、起拍价和最低加价。
- 有效出价回复：`【球队名称】出价有效：⭐120⭐，倒计时重置为 30 秒。`
- 每次有效出价生成新的截止时间和 epoch，旧 epoch 的倒计时任务自动失效。
- 无效出价记录结果和原因，但不改变最高价或截止时间。

### 6.3 倒计时

倒计时只发送以下节点：

```text
20、10、3、2、1
```

- 不发送 `30`、`5`、`4` 或 `0`；
- 新的有效出价将倒计时重置到 30 秒；
- 旧 epoch 的未发送倒计时由 outbox 领取逻辑判定为失效；
- 到期后直接发送计算结果或流拍通知。

### 6.4 结束与审核

- 倒计时结束后，球员进入 `PENDING_REVIEW`，计算结果只作为待审核记录；
- 无有效出价时标记 `NO_BID`；
- 不自动确认成交；
- 不自动开始下一位；
- 管理员在群内发送 `下一位`后才启动下一位球员；
- 管理员在后台最终确认成交、流拍或作废；
- 批次全部结束后发送完成提示，最终结果仍以人工审核为准。

## 7. 故障与恢复

- Bridge 离线、设备心跳超时、发送结果不确定或服务重启歧义时，活跃拍卖进入 `RECOVERY_REQUIRED`；
- 当前球员停止倒计时并保存剩余时间；
- 系统不自动重发结果不确定的消息；
- 管理员核对群消息后，通过现有恢复流程和 `继续拍卖`恢复；
- 恢复消息和后续倒计时仍只发送到批次绑定群；
- 群功能被活跃拍卖保护，不能在恢复前被关闭。

## 8. 数据迁移与兼容性

迁移按现有配置回填功能：

- 存在赛程来源的群增加 `SCHEDULE_QUERY`，`createdByAdminId` 取该群最早创建的赛程来源管理员；
- 被任一已有拍卖批次引用的群增加 `PLAYER_AUCTION`，`createdByAdminId` 取该群最早创建的拍卖批次管理员；
- 同时满足两项的群获得两个功能；
- 无法从现有数据推断用途的群保持空功能集合，由管理员显式配置；
- 历史回填按创建时间和记录 ID 排序，保证重复执行或不同数据库环境得到相同结果；
- 不删除或重建群绑定，不改变 `groupBindingId`；
- 不修改身份绑定、赛程来源、入站消息、outbox、批次、球员、出价或审核记录。

现有 Bridge 仍按后台下发的启用群列表读取消息。功能判断集中在服务端，避免需要按群同步复杂规则到 Windows；Bridge 只负责可靠读取、上传和发送。

## 9. 测试与验收

自动化测试至少覆盖：

1. 合同层接受零个、一个和两个功能，并拒绝未知值和重复值；
2. 迁移正确回填查询群、拍卖群和综合群；
3. 同一联赛可以保存多个不同微信群；
4. 查询群只处理赛程命令，数字消息静默忽略；
5. 拍卖群只处理拍卖命令和数字出价，赛程命令静默忽略；
6. 综合群同时处理两类命令；
7. `帮助`只显示当前群已启用功能；
8. 拍卖批次下拉框只包含可用拍卖群；
9. 活跃批次阻止关闭群或移除拍卖功能；
10. 所有拍卖 outbox 均使用批次绑定群的稳定 ID；
11. 有效出价重置 30 秒，倒计时只产生 `20、10、3、2、1`；
12. 旧 epoch 倒计时失效，不发生重复发送；
13. 拍卖结束进入人工审核且不会自动下一位；
14. 多个拍卖群可由管理员分别创建和运行批次；
15. Bridge 异常触发恢复状态并保持群隔离。

真实 Windows 验收使用一个查询群和一个拍卖群：

- 查询群验证 `查询赛程`、`我的赛程`和数字静默；
- 拍卖群使用至少两支已绑定球队完成一位球员的竞价；
- 核对星号价格格式、有效出价提示、`20、10、3、2、1`节点、待审核结果和管理员手动 `下一位`；
- 验证服务端 `SENT` 回读、无重复 outbox、设备未熔断。

## 10. 不在本次范围

- 不增加跨联赛群绑定；
- 不自动决定同一联赛能否同时运行多个拍卖；
- 不自动审核成交结果；
- 不自动开始下一位；
- 不新增群外通知渠道；
- 不改变微信身份绑定方式；
- 不承诺规避微信平台风控，继续采用白名单群、专用账号、低频发送和人工验收。
