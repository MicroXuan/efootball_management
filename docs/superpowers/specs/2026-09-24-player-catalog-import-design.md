# 球员库与批量导入设计

## 1. 目标

本阶段建立首个可持续维护的球员数据闭环：开发者通过 CSV 或 JSON 创建导入批次，系统完成规范化、校验、重复检测和差异计算，经授权人员确认后事务发布；微信小程序仅查询已经发布的数据，并提供球员卡搜索、筛选、列表和详情页面。

成功标准：

- 同一来源的同一外部记录可以幂等地重复导入，不产生重复球员卡；
- 新增、更新、无变化和无效记录在发布前可被准确区分；
- 含无效记录的批次不能发布，发布失败不会留下部分正式数据；
- 游客无需登录即可浏览已发布的球员、球员卡和卡包；
- 小程序具备搜索、筛选、分页、空状态、错误重试和详情展示；
- 现有登录、资料和游戏账号能力不回归。

## 2. 范围

### 2.1 本阶段包含

- 球员、球员卡、卡包、技能、卡片属性和发布版本的数据模型；
- 数据源、导入批次、导入记录和差异的数据模型；
- CSV 与 JSON 文件适配器；
- 文件级、记录级和关联级校验；
- 新增、更新、无变化和无效差异计算；
- 管理 API 与本地导入命令；
- 球员、球员卡和卡包公开查询 API；
- 小程序球员库首页、搜索筛选和球员卡详情；
- 自有深色绿金卡片模板及无图占位展示。

### 2.2 本阶段不包含

- 自动爬虫、游戏客户端逆向或未经授权的第三方私有接口；
- 定时第三方数据同步；
- 第三方卡图下载或缓存；
- 独立 Web 管理后台；
- 收藏、阵容、球员对比和自动加点；
- 工资计算、工资版本和工资帽；
- 赛事与战队功能。

## 3. 架构

系统新增两个后端业务模块和一组小程序页面：

- `player-catalog` 负责正式球员数据、发布版本及公开查询；
- `player-import` 负责数据适配、规范化、校验、差异计算和发布；
- 小程序球员库只依赖 `player-catalog` 的公开查询接口，不访问导入暂存数据。

导入适配器输出统一的规范化记录。CSV、JSON 以及未来获得授权的 API 适配器都必须使用同一套校验、差异和发布服务，不能各自直接写入正式表。

```text
CSV / JSON
    ↓
导入适配器
    ↓
规范化与校验
    ↓
暂存批次和差异记录
    ↓
授权人员确认发布
    ↓
数据库事务写入正式表并生成发布版本
    ↓
公开查询 API
    ↓
微信小程序球员库
```

## 4. 数据模型

所有新表沿用 UUID 主键、`created_at`、`updated_at` 和 snake_case 数据库命名。对外契约使用 camelCase。

### 4.1 正式目录

#### `football_players`

- 中文名、英文名、简称；
- 国籍和现实俱乐部使用首版字符串字段，后续再拆字典表；
- 搜索规范化字段，用于大小写无关及空白归一化查询；
- 发布状态和最近发布版本。

#### `football_player_sources`

- 关联现实球员、数据源和该来源的球员外部编号；
- `source_id + external_id` 唯一；
- 保存来源更新时间，避免把第三方标识直接固化为现实球员主键。

#### `card_packs`

- 数据源与外部编号；
- 中文名、英文名、赛季、发布日期；
- 封面 URL、发布状态和最近发布版本；
- `source_id + external_id` 唯一。

#### `player_cards`

- 数据源与外部编号；
- 所属现实球员和可选卡包；
- 卡片名称、位置、总评、卡片类型、比赛风格、状态和图片 URL；
- 最近发布版本及来源更新时间；
- `source_id + external_id` 唯一。

#### `player_card_attributes`

- 每张卡一条记录；
- `attributes_json` 保存初始或满级能力属性；
- 首版不把每项能力拆为列，避免适配器字段差异污染核心结构。

#### `skills` 与 `player_card_skills`

- 技能以规范化代码唯一；
- 保存中英文展示名；
- 卡片与技能多对多关联。

#### `catalog_releases`

- 发布序号、导入批次、发布人、发布时间；
- 新增、更新和无变化数量摘要；
- 发布后不可修改。

### 4.2 导入暂存

#### `data_sources`

- 来源代码、名称、来源类型和启用状态；
- 首版内置 `manual` 来源；
- 来源代码唯一且发布后不能变更。

#### `import_batches`

- 来源、格式、原始文件名、内容 SHA-256；
- 状态、总记录数及各差异类型数量；
- 创建人、失败原因、发布时间和对应发布版本；
- `source_id + checksum` 唯一，使相同来源的相同文件幂等。

状态机：

```text
UPLOADED → VALIDATED → READY → PUBLISHED
    │          │          │
    └──────────┴──────────┴→ FAILED / CANCELLED
```

`PUBLISHED`、`FAILED` 和 `CANCELLED` 为终态。

#### `import_records`

- 批次内序号和外部编号；
- 原始 JSON、规范化 JSON 和内容校验值；
- 差异类型、字段级差异、校验错误；
- 匹配到的正式球员和球员卡；
- 同一批次内序号唯一。

差异类型：

- `CREATE`：正式库不存在该来源外部编号；
- `UPDATE`：存在且来源拥有的字段发生变化；
- `UNCHANGED`：规范化内容与正式数据一致；
- `INVALID`：格式、业务规则或关联校验失败。

## 5. 导入格式

JSON 接受记录数组。CSV 第一行必须是表头。两种格式映射到相同的规范化字段：

- 必填：`externalId`、`playerNameZh` 或 `playerNameEn`、`cardName`、`position`、`overallRating`、`cardType`；
- 可选：球员简称、国籍、俱乐部、卡包外部编号与名称、赛季、发布日期、比赛风格、状态、图片 URL、技能、属性和来源更新时间；
- 技能在 CSV 中用英文逗号分隔；
- 属性在 JSON 中为对象，在 CSV 中使用 `attributesJson` JSON 字符串。

位置和卡片类型使用稳定代码，展示文案由客户端映射。总评首版允许 `1..110`。时间字段必须为 ISO 8601 日期或时间。字符串在比较前去除首尾空白并规范化连续空白，但展示值保留合法大小写和重音字符。

## 6. 校验与差异规则

### 6.1 文件级

- 拒绝空文件、不支持的格式和无法解析的编码；
- 单批次最多 5,000 条记录；
- 相同来源和内容校验值返回已有批次；
- 批次创建后保存原始记录，不保存未经授权的远程素材副本。

### 6.2 记录级

- 外部编号、名称、卡片名称、位置、总评和卡片类型必须合法；
- 图片字段仅接受 `https` URL；
- 技能去重，空技能不入库；
- 属性必须是有限深度的 JSON 对象，不接受数组顶层；
- 同一批次出现相同外部编号时，冲突记录均标记 `INVALID`。

### 6.3 关联级

- 使用 `source_id + external_id` 匹配球员卡；
- 使用来源内的球员外部编号匹配现实球员；没有提供球员外部编号时，以规范化中英文名匹配，出现多个候选即标记歧义；
- 卡包存在外部编号时按来源匹配，不以展示名跨来源合并；
- 更新只覆盖该数据源拥有的字段；
- 不通过一次缺失记录自动下架正式卡片，下架必须显式导入状态。

## 7. 发布语义

- 只有 `READY` 且不存在 `INVALID` 记录的批次可以发布；
- 发布接口必须幂等，已发布批次再次调用返回原发布结果；
- 发布在单个数据库事务内完成；任何写入失败时，正式数据、关联和发布版本全部回滚；
- `CREATE` 创建或关联现实球员、卡包、球员卡、技能和属性；
- `UPDATE` 仅更新发生变化且由当前来源拥有的字段；
- `UNCHANGED` 不写正式业务数据，但计入发布摘要；
- 每次成功发布创建不可变的 `catalog_releases` 记录；
- 历史发布不复制全量球员库，正式记录保存最近发布版本，导入记录保留当次原始值与差异。

## 8. 权限

公开查询接口允许游客访问。导入、差异查看和发布必须登录，并要求平台作用域的内容编辑权限。

新增权限代码：

- `catalog.import.create`；
- `catalog.import.read`；
- `catalog.import.publish`。

本地命令不绕过业务服务。命令必须显式提供执行用户或服务身份，并经过相同的权限或受控开发环境检查。

## 9. API

### 9.1 公开查询

- `GET /players`：按关键字、位置、总评范围、卡片类型和卡包筛选，使用游标或稳定分页；
- `GET /players/:id`：现实球员及其已发布卡片；
- `GET /player-cards/:id`：单张已发布卡片详情；
- `GET /card-packs`：已发布卡包分页列表；
- `GET /card-packs/:id`：卡包及其已发布球员卡。

默认排序为发布时间降序、总评降序和 ID 升序，保证分页稳定。不存在或未发布的资源统一返回 404。

### 9.2 管理接口

- `POST /admin/player-imports`：提交来源、文件名、格式和内容；
- `GET /admin/player-imports/:id`：批次状态和统计；
- `GET /admin/player-imports/:id/records`：按差异类型和错误状态查看明细；
- `POST /admin/player-imports/:id/publish`：确认并发布批次；
- `POST /admin/player-imports/:id/cancel`：取消未发布批次。

上传首版使用 JSON 请求体承载 UTF-8 文本，不引入对象存储和 multipart。超出合理请求体大小的文件由本地命令读取并调用同一业务服务。

## 10. 本地命令

提供两个命令入口：

- `player-import validate <path> --source manual`：创建批次并输出统计、错误和批次 ID；
- `player-import publish <batch-id>`：发布已经就绪的批次。

命令输出必须适合人工阅读，并使用非零退出码表示解析、校验、权限或发布失败。命令只负责输入输出，业务判断全部复用 `player-import` 服务。

## 11. 微信小程序

### 11.1 导航

新增底部双入口：

- `球员`：球员库首页，作为公开默认入口；
- `我的`：沿用现有登录、资料和游戏账号能力。

赛事入口在后续阶段加入。未登录用户进入“我的”时转到登录流程，浏览球员不触发登录。

### 11.2 球员库首页

- 深色背景、绿色主色和金色强调色；
- 顶部标题、搜索框和位置、卡片类型、卡包快捷筛选；
- 按卡包分组展示球员卡；
- 卡片展示总评、位置、中英文名、比赛风格和卡片类型；
- 无授权图片时使用自有模板和姓名首字母占位；
- 支持首次加载、下拉刷新、触底分页、空结果和错误重试。

### 11.3 搜索与筛选

- 中文名、英文名模糊查询；
- 位置、总评区间、卡片类型和卡包筛选；
- 条件变化后清空旧游标并重新加载；
- 首版不提供复杂排序选项。

### 11.4 球员卡详情

- 自有卡面或授权图片；
- 中英文名、位置、总评、卡片类型和比赛风格；
- 国籍、现实俱乐部和所属卡包；
- 能力属性与技能列表；
- 同一现实球员的其他已发布卡片；
- 接口错误、资源下架和无图状态都有明确反馈。

## 12. 错误处理与可观测性

- 导入错误返回稳定错误代码和可定位的记录序号、字段及原因；
- 文件级失败将批次置为 `FAILED`，记录级错误保留批次但阻止进入 `READY`；
- 发布冲突、重复发布和非法状态转换使用明确的 409 响应；
- 请求日志记录 request ID、批次 ID、来源、操作者和结果，不记录完整导入内容；
- 小程序将网络错误、空结果、资源不存在和服务错误区分展示；
- 图片加载失败回退至本地占位，不影响其他数据展示。

## 13. 测试策略

### 13.1 契约测试

- 导入请求、查询筛选和分页响应；
- 位置、卡片类型、批次状态和差异类型枚举；
- 非法字段、边界值和未知字段策略。

### 13.2 单元测试

- CSV/JSON 解析和规范化；
- 总评、URL、日期、技能和属性校验；
- 同批次重复、正式库匹配和歧义；
- `CREATE / UPDATE / UNCHANGED / INVALID` 差异计算。

### 13.3 数据库与 API 测试

- 首次发布创建完整关联；
- 更新发布只修改来源拥有的字段；
- 相同内容导入及重复发布保持幂等；
- 无效批次不能发布；
- 发布中途失败完整回滚；
- 游客可查询，普通用户不能调用管理接口，内容编辑可导入和发布；
- 过滤、稳定分页、未发布数据隔离和 404 行为。

### 13.4 小程序测试

- 查询参数构造；
- 卡包分组和展示模型；
- 条件变化重置分页；
- 触底分页去重合并；
- 卡片详情属性和技能展示模型；
- 加载、空状态、错误和图片回退。

最终运行仓库的 lint、类型检查、单元测试、端到端测试和构建命令，确认身份模块没有回归。

## 14. 合规与素材策略

- 产品不抓取 KONAMI 游戏客户端或逆向私有接口；
- 数据来源必须保存来源代码和外部编号，未来接入 API 前必须确认授权和使用条款；
- 第三方图片 URL 只有在取得展示授权后才允许进入正式数据；
- 默认卡面由本项目自行设计，不复制第三方卡框、Logo 或受保护素材；
- 提供来源停用和数据下架能力，但物理删除不属于常规导入流程。

## 15. 后续扩展

本阶段完成后，可以在不改变正式目录和小程序查询接口的前提下增加：

- 获授权的第三方 API 适配器和定时任务；
- 独立 Web 审核后台；
- 数据纠错工作流；
- 收藏、对比、阵容和工资版本；
- 图片对象存储、授权校验和 CDN。
