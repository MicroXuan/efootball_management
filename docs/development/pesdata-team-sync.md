# PESDATA 球队目录同步

PESDATA 只作为球队“队壳”元数据来源：球队名称、简称和队徽。同步不会读取或改动阵容、球员、用户、联赛编号、联赛称呼、财务、比赛结果或赛季资格。

## 前置条件

- 先确认已获得同步球队名称和队徽并保存到自有对象存储的授权。
- 配置现有 PESDATA 客户端所需的访问参数和 `PESDATA_SIGNATURE_SEED`。
- 配置对象存储。远端队徽会经过 HTTPS、重定向次数、响应体大小、图片签名及像素尺寸校验后，以稳定对象键保存。
- 命令中的 `--actor` 必须是执行同步的平台管理员 UUID。

小程序和后台业务页面只读取本地 API 与对象存储，不会在用户请求链路中访问 PESDATA。

## 执行同步

在仓库根目录运行：

```bash
# 抽样同步，默认 2 支，可指定 1-5000
pnpm --filter @efm/api sync:pesdata -- teams sample --actor <管理员UUID> --limit 2

# 增量同步；内容校验值未变化的球队会跳过
pnpm --filter @efm/api sync:pesdata -- teams incremental --actor <管理员UUID>

# 全量同步；同时识别数据源中已消失的球队
pnpm --filter @efm/api sync:pesdata -- teams full --actor <管理员UUID>

# 从失败的同步任务继续
pnpm --filter @efm/api sync:pesdata -- teams resume <同步任务UUID> --actor <管理员UUID>
```

同一时刻只允许一个球队目录同步任务运行。协议结构异常会使整个任务失败，避免把不可信的数据写入候选目录；单支球队的普通下载或映射失败会记录在同步明细中，可修复后继续任务。

## 审核和发布

同步完成后，新建、更新和来源缺失项只进入“待审核”，不会自动发布。平台管理员在联赛球队页面的“PESDATA 球队目录同步”区域逐项查看，然后选择：

- **发布**：将候选名称、简称及自有对象存储队徽写入本地球队目录。
- **忽略**：保留现有目录内容，并记录本次人工决定。

全量同步发现来源缺失时，目录项会标记为“来源待确认”。系统不会自动删除目录项，也不会释放联赛中已经占用的队壳。管理员确认后再进行后续人工处理。

所有发布、忽略和同步操作均记录具体审计动作，不使用“其他后台操作”这类模糊描述。
