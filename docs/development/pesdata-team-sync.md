# PESDATA 球队目录同步

PESDATA 只作为球队“队壳”元数据来源：球队名称、简称和队徽。同步不会读取或改动阵容、球员、用户、联赛编号、联赛称呼、财务、比赛结果或赛季资格。

## 前置条件

- 先确认已获得同步球队名称和队徽并保存到自有对象存储的授权。
- 配置现有 PESDATA 客户端所需的访问参数和 `PESDATA_SIGNATURE_SEED`。
- 配置对象存储。远端队徽会经过 HTTPS、重定向次数、响应体大小、图片签名及像素尺寸校验后，以稳定对象键保存。
- 命令中的 `--actor` 必须是执行同步的平台管理员 UUID。

小程序和后台业务页面只读取本地 API 与对象存储，不会在用户请求链路中访问 PESDATA。

## 后台操作入口

平台管理员登录后台后，进入 **数据同步**（`/platform/data-sync?tab=teams`）。球队同步已从单个联赛的“用户与球队”页面移除，因为 PESDATA 队壳是全平台共享数据，不属于某一个联赛。

- **抽样同步**：最多 100 支，用于验证来源结构和队徽存储；
- **增量同步**：日常使用，只处理新增、变更和上次失败项；
- **全量同步**：扫描全部来源球队，并识别来源缺失项，启动前必须二次确认；
- **继续任务**：在失败且可恢复的历史任务行显示，不会对不可恢复任务误开放。

任务异步执行，页面每 2.5 秒刷新活动任务状态。关闭页面、刷新浏览器或切换页签都不会停止任务。任务历史和队壳差异均为服务端分页；每页只能选择 20 或 50 条。审核列表默认只显示“待审核”和“失败”，管理员可主动查看已发布、已驳回数据，并可按变化类型、来源联赛、球队名称/来源 ID、错误码筛选。

## CLI 回退

CLI 只用于后台暂时不可用的运维场景。球队 CLI 的 `--actor` 必须是 `admin_accounts.id` 中有效的平台管理员 UUID。

在仓库根目录运行：

```bash
# 抽样同步，默认 2 支，可指定 1-5000
pnpm --filter @efm/api sync:pesdata -- teams sample --actor <管理员UUID> --limit 2

# 增量同步；内容校验值未变化的球队会跳过
pnpm --filter @efm/api sync:pesdata -- teams incremental --actor <管理员UUID>

# 全量同步；同时识别数据源中已消失的球队
pnpm --filter @efm/api sync:pesdata -- teams full --actor <管理员UUID>

# 从失败的同步任务继续
pnpm --filter @efm/api sync:pesdata -- teams resume <同步任务UUID> --actor <管理员UUID>
```

同一时刻只允许一个球队目录同步任务运行。协议结构异常会使整个任务失败，避免把不可信的数据写入候选目录；单支球队的普通下载或映射失败会记录在同步明细中，可修复后继续任务。

## 审核和发布

同步完成后，新建、更新和来源缺失项只进入“待审核”，不会自动发布。平台管理员在平台级“数据同步 → 球队队壳”中查看当前正式数据与候选数据，然后选择：

- **批量发布**：将候选名称、简称及自有对象存储队徽写入本地球队目录，一次最多 100 条；
- **批量驳回**：保留现有目录内容，并记录本次人工决定；
- **重试失败项**：只重试明确选中的失败条目。

批量接口可能部分成功。页面会分别显示成功数量和每个失败项的具体错误码，不会把部分成功伪装成全部成功。已发布项默认不显示，避免操作页面被历史数据淹没。勾选项可跨分页保留，一次最多 100 条；切换同步任务或筛选条件时会清空勾选，避免误操作另一组数据。

全量同步发现来源缺失时，目录项会标记为“来源待确认”。系统不会自动删除目录项，也不会释放联赛中已经占用的队壳。管理员确认后再进行后续人工处理。

所有发布、忽略和同步操作均记录具体审计动作，不使用“其他后台操作”这类模糊描述。批量发布、驳回和重试会先创建整单审计记录，再写入请求数、成功数、失败数及失败码；每条成功变更仍保留自己的原子审计记录。

## 服务重启与恢复

同步偏移、任务心跳、候选队壳和审核状态都持久化在数据库中。重启 API 服务不会丢失这些数据，也不会自动续跑未完成任务。任务运行期间由独立定时心跳续租，不依赖一页数据处理结束才续租。租约过期后，系统把遗留的 `PENDING`/`RUNNING` 任务标记为 `FAILED`，错误码为 `PROCESS_INTERRUPTED`；管理员确认来源服务和配置正常后，在历史任务行点击“继续任务”。同一数据域仍只允许一个活动任务，重复点击或并发启动会返回冲突，不会创建两个同步任务。每个执行进程还持有独立所有权令牌，租约被回收后旧进程不能继续写入候选项、检查点或最终状态。
