# 联赛展示与管理员绑定验收手册

本手册验证“后台发布联赛与赛季、管理员绑定用户球队、小程序只读展示”的完整本地闭环。

## 1. 启动前检查

在项目根目录执行：

```bash
export PATH=/opt/homebrew/opt/node@24/bin:$PATH
set -a
source .env
set +a
pnpm dev:db
pnpm db:migrate
pnpm db:status
pnpm --filter @efm/api exec prisma db seed
```

本地图片配置应为：

```dotenv
STORAGE_PROVIDER=local
LOCAL_STORAGE_DIR=.data/uploads
PUBLIC_API_BASE_URL=http://127.0.0.1:3000
```

终端 A 启动 API：

```bash
pnpm start:api
```

终端 B 启动后台：

```bash
pnpm --filter @efm/admin-web dev
```

浏览器访问 `http://127.0.0.1:4173/login`。用户名取自 `.env` 的 `LOCAL_ADMIN_USERNAME`；明文密码由本地保管，不记录在本手册。

## 2. 创建联赛并验证图片

1. 登录后台，进入“联赛管理”。
2. 输入联赛名称、简称和说明。
3. 不选择“国服/国际服”直接提交，预期：表单阻止提交。
4. 选择一张真实 JPG、PNG 或 WebP，文件大小不超过 2 MiB，预期：保存成功并能显示图片。
5. 选择大于 2 MiB 的图片，预期：后台提示“图片大小不能超过 2MB”，不会发送保存请求。
6. 将脚本或文本文件改名为 `.png` 后尝试上传，预期：即使客户端被绕过，API 仍以文件签名不合法拒绝。
7. 选择“国服”或“国际服”并保存，预期：列表正确显示版本、说明和图片。

## 3. 创建并指定当前赛季

1. 进入联赛的“赛季管理”。
2. 创建一个时间顺序合法的赛季。创建完成后，预期：赛季存在，但只有点击“设为当前赛季”后才成为当前赛季。
3. 在尚未设置当前赛季时到“用户与球队”绑定用户，预期：提示“请先在赛季管理中设置当前赛季，再绑定球队”，数据库不产生孤立球队或报名记录。
4. 返回赛季管理，把刚创建的赛季设为当前赛季。

## 4. 获取用户编号并绑定球队

1. 在微信开发者工具导入 `apps/miniprogram`，确保 API 地址指向本机 API。
2. 用户完成微信登录，进入底部“我的”。
3. 预期：页面显示 6 位用户编号；即使尚未绑定球队、没有头像或昵称也不能崩溃。点击编号可复制。
4. 后台进入该联赛“用户与球队”，输入 6 位编号并点击“查找用户”。
5. 填写球队编号、球队名称、简称并创建。
6. 预期：球队创建成功，并自动生成当前赛季 `APPROVED` 报名；无需游戏账号，也不需要用户再次确认。
7. 重复绑定同一用户或同一球队编号，预期：后台显示明确冲突，且不会生成多余报名记录。

## 5. 验证实时展示

1. 后台“赛季管理”确认当前赛季参赛球队数增加 1。
2. 小程序进入底部“联赛”，下拉刷新。
3. “全部联赛”应显示图片、名称、说明、国服/国际服、当前赛季和当前赛季已入组人数。
4. “我的联赛”应只显示管理员已为当前用户绑定球队的联赛。
5. 进入底部“我的”，应显示只读身份、6 位编号和各联赛独立球队；不应出现个人资料保存、游戏账号、创建联赛或编辑球队入口。
6. 点击球队可查看只读阵容、工资帽、财务流水和转会窗口。

## 6. 切换当前赛季

1. 后台再创建一个新赛季，并将其设为当前赛季。
2. 小程序联赛页下拉刷新。
3. 预期：联赛立即显示新当前赛季；新赛季人数从其实际 `APPROVED` 报名数开始，不会把旧赛季球队自动迁入。
4. 如需旧球队参加新赛季，在“当前赛季球队”中明确勾选后加入；重复加入应安全跳过。

## 7. 自动化发布门禁

```bash
export PATH=/opt/homebrew/opt/node@24/bin:$PATH
set -a
source .env
set +a
pnpm db:status
pnpm verify
git diff --check
```

预期：数据库迁移为最新；所有 lint、类型检查、单元测试、端到端测试和构建通过；无空白错误。

## 8. 兼容边界

- 旧游戏账号与自助球队资料数据暂不删除，以便读取历史赛事记录。
- 旧 `/me/game-accounts` 和 `/me/team-profile` 写接口带 `Deprecation: true` 响应头。
- 新小程序活动页面不调用上述写接口；旧页面文件保留在代码库中，但未注册到 `app.json`，不能从产品流程进入。
