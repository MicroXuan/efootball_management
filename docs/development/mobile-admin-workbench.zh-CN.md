# 手机管理员工作台

入口：后台顶栏「手机工作台」，或直接访问后台同域名的 `/mobile`。
使用现有管理员账号，未登录时登录后返回原手机页面；不新增账户、数据库模型或 API。
平台管理员可选择所有可管理联赛，联赛管理员仅显示已授权联赛。浏览器按管理员账号记住最近选择的联赛。

## 第一版范围

- 工作台：所选赛季已发布比赛的待录比分数量，以及此联赛全部赛季的待审核转会数量；各显示前三条并提供完整列表入口。
- 赛程／比分：选择赛季、轮次、比分状态，按球队名称或编号搜索。默认选择进行中赛季，没有则使用后台返回的第一个赛季。只展示已发布赛程。一次展示 20 条，可继续显示。
- 比分：0—99 的整数，主客队顺序明确；新录入与修正均要求原因。先核对，再提交官方比分。沿用后台服务的赛事状态、争议阶段、淘汰赛胜负、乐观锁、幂等与审计规则。
- 转会：待审核、待对方确认、全部记录；查看球员、双方、报价、申请说明和处理记录。只有待管理员审核的申请可批准／驳回，审核理由必填。
- 手机界面独立于桌面侧栏，但沿用登录会话及 API 客户端。页面中的比赛时间使用项目既有北京时间格式。

比分使用已发布赛事列表和比赛接口读取，使用联赛管理员比分接口写入。转会复用现有申请查询及审核接口。赛季和赛事列表处理游标分页。任一赛事读取失败会显示错误，不将部分赛程当成完整结果。
切换联赛或赛季时清除旧内容，忽略已过期的异步响应。重复点击提交被锁定，网络失败后重试相同提交沿用幂等键；编辑内容后生成新键。服务端版本冲突时提示关闭窗口并刷新核对。

## 2026-10-30：管理员转会、晋级与手机布局

本轮扩展已在 `dev` 实现，需发布对应 API 和后台前端后才在目标环境生效；本轮功能无新增数据库迁移。工作树中其他功能的迁移应按其独立发布说明处理。

### 使用方式

- 转会管理：选择联赛、赛季 →「办理转会」→ 转出球队 → 当前球员 → 转入球队 → 填写正整数金额（资金）及原因 →「核对转会」→「确认办理转会」。保留原有待审核、待确认、全部记录入口。审核列表仍覆盖联赛全部赛季，直接办理使用页面所选赛季。
- 淘汰赛晋级：赛程 / 比分 → 找到淘汰赛对阵 →「裁定晋级」→ 选择主队或客队并填写原因 → 核对后确认。已有裁定可点「更正晋级」。晋级结果计入「已有赛果」，不再留在「待录比分」中。
- 裁定不会虚构比分；已有比分被替换时明确提示。存在争议或下一轮已进行时，沿用服务端规则拒绝修改。转会仍校验权限、窗口、归属、球队人数、工资帽和手续费。

### 实现与验证

- 晋级 HTTP：`POST /v1/admin/leagues/:leagueId/competitions/:id/matches/:matchId/advancement`，使用管理员登录和联赛权限，必填 `Idempotency-Key`；正文包含 `winnerParticipantId`、`expectedVersion`、`reason`。复用已有晋级、签表推进及审计方法。
- 直接转会复用 `/v1/admin/roster/transfers`，幂等键在正文。重复点击锁定，不确定失败保留同一键；修改内容后生成新键。球队、赛季切换清除旧选择，并丢弃迟到响应。
- 手机页面：320px 筛选栏单列、卡片按钮等宽、长队名换行；新增晋级选择卡和转会核对页。弹窗独立滚动，输入字号 16px，操作按钮至少 44px，底部导航保留安全区域。
- 后台源码 Vitest：61 文件、276 项通过；API 模拟单元测试 15 项通过；小程序我的联赛/球队详情 11 项通过。API TypeScript、后台生产构建通过。构建保留既有较大分包提示。
- 后台顶层 Vitest 会误收集既有 `scripts/staging-release.test.mjs`（Node 测试），出现“未找到 Vitest suite”；本轮用 `pnpm --filter @efm/admin-web test --run src` 完成全部后台源码回归，未修改该独立发布脚本。
- 浏览器所有 `/v1/` 请求均被模拟，未写共享数据库。检查 320/375/390/768px 的比分、晋级、直接转会、审核、正常/禁用态、边界及短视口下的提交操作。截图保存于 `output/mobile-admin-actions/`。
