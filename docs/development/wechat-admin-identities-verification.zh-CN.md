## 高频与故障证据

`test_mixed_chat_load_compacts_members_and_preserves_commands_across_restart` 输入 1500 条消息，30 个联系人，普通聊天与查询/报价混合：成员记录合并为30条；150条有效命令持久化后重启，分批读取顺序不变；成员队列确认不改变命令队列。普通聊天正文不在成员元数据中。

另有独立测试覆盖上传失败重试、旧 ack 不删除新观察、SQLite 重启补传、停用群丢弃观察、入站 API 超时保留命令、发送结果不确定不重发。成员上传独立线程，批次上限100，退避最长60秒；每次扫描最多2000行并轮换会话起点。

这些是正确性测试，不是实机吞吐或端到端延迟指标。上线前记录入站、成员观察和出站队列深度、最老等待时间，以及查询/报价从微信发出到确认的 p50/p95；不得用单元测试执行耗时替代。

## Windows 实机待验收

- [ ] 固定微信版本，doctor通过，默认关闭真实发送。
- [ ] 普通授权群发言可发现稳定发送者；昵称缺失、改名、同名不同人、跨群同人均正确。
- [ ] 未授权群、未知发送者、自发消息和普通私聊不进入观察队列；普通聊天不回复。
- [ ] 平台管理员按六位用户编号核对身份并绑定，无 OTP；联赛管理员只读、普通用户无法写入。
- [ ] 后台绑定后新“我的赛程”及新报价生效；解绑/停用后拒绝；绑定前已拒绝报价不得重放。
- [ ] 断网/重启补传、旧 API 404 独立退避，不阻断原竞价；观察积压可见。
- [ ] 锁屏、微信退出、API失联后发送按既有策略停止；恢复后不重复出价或发送。
- [ ] 并发管理员操作明确冲突；含历史报价的身份不能换给其他 User。
- [ ] 更换机器人账号停 Bridge 后重启，确认 `get_self_info().username` 对应真实新账号，心跳停用原设备与身份，不能继承。运行中切号可能受依赖缓存影响，不宣称即时检测。

## 部署与保守边界

目标 `db:status` → 受控迁移 → API/后台 → Bridge → Windows验收 → 按现有部署流程启用真实发送。迁移为 `20261026120000_wechat_observed_members`，需在新 API 承接流量前应用；不能把本地迁移成功视为目标环境已迁移。

身份关联是设备级、跨其所有群生效，User关联不授予Admin权限。当前不允许把已有历史报价的联系人换给其他用户，也不允许自动覆盖同User的其他身份行（含停用行），以保留历史外键含义；这类更正需要后续专门的迁移流程。成员发现只覆盖实际观察到的授权群发言者，不提供完整群成员目录。


## 独立审阅结论与修复

审阅发现并修复两项重要问题：首次补传的报价按微信发送时间检查是否早于当前身份生效时间，旧报价不得借新身份进入拍卖；实际 Bridge 心跳携带数据库返回的稳定账号标识，未知身份或账号变更未确认时停止接收上传/成员同步/发送。账号来源参照固定依赖 1.2.5.1 的 `get_self_info()`（返回 `username`），接口说明见 [依赖指南](https://github.com/fanyuantaier/wechatauto-replica/blob/main/GUIDE.md)。真实账号与缓存行为仍需 Windows 验收。

暂缓的小项：成员列表已有按群筛选和分页，尚无“仅未绑定”状态筛选，成员较多时需要逐页查看。
