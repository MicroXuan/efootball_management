# 退群后仍显示可绑定：修复与验收

原实现从微信会话列表发现群，API 只 upsert 历史群记录，不更新已退出群的可用状态。

Bridge 改用固定依赖 wechatauto-replica 1.2.5.1 的 `get_groups()`，只上报成员中包含当前机器人账号的群。已登录且本地数据库可用时，心跳声明 `observedGroupsComplete`。服务端在设备事务锁内将完整快照之外的群标记为不可用，同时刷新本次群记录；重新入群后可以恢复。旧版心跳或未登录心跳不会导致批量隐藏群。历史群、绑定与业务数据均保留，不执行删除。

后台两个可选群接口过滤不可用群，保存绑定时拒绝不可用群。Bridge 授权列表也过滤不可用群。

## 发布顺序

1. 在目标环境执行 `pnpm db:status`，核对主机和库名。
2. 按受控部署流程应用 `20261030160000_wechat_group_availability`，再确认迁移状态。
3. 发布 API，再更新 Windows Bridge 并重启；旧版 Bridge 不会主动移除历史群。
4. 等待新 Bridge 心跳，刷新后台，验收群列表和绑定保存。

本次只读检查发现目标环境尚未应用该迁移，未执行线上迁移或发布。API 单元测试使用模拟 Prisma，显式指定本机 efm_test 连接，跳过依赖真实数据库的全局清理 hook；未产生数据库测试记录。

## 真实环境验收

- 用机器人登录账号核对“静安青年体育公园散客群（2）”已退出，确认 Windows 本地成员数据已经刷新。
- 保留聊天记录时，群也不应再出现在后台可选群列表；其他仍在的群保持可用。
- 退出全部群、重新入群、机器人离线后恢复分别检查。
- 若微信本地成员数据仍有旧缓存，不能声称已成功识别退群；需先核对实际成员查询结果。
- 若退出的是个人账号而机器人账号仍在群中，该群仍可由机器人绑定。
- 检查目标 API 实际响应和后台解析，复测球队列表的现役/已退出、球队详情以及小程序我的联赛。
