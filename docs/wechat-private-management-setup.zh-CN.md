# 管理员私聊：晋级、转会与拍卖管理

沿用私聊录分的 AdminAccount 绑定和联赛授权。普通用户的 User 关联只用于查询、竞价，不授予管理权；群聊管理命令不再执行。管理员操作自己获授权的联赛，平台管理员可切换联赛。

## 启用顺序

1. 停止 Bridge，安排 API 更新窗口，核对部署数据库主机和库名并备份。
2. 更新代码后先运行 `pnpm db:status`，再按受控部署流程执行 `pnpm db:migrate`（migrate deploy），然后 `pnpm db:status`、`pnpm db:generate`。本次新增迁移为 `20261028130000_wechat_private_management`；私聊录分迁移也必须已应用。不可使用开发态迁移。
3. 迁移完成后再启动新 API、后台与小程序代码。新增比赛字段会参与查询，关闭功能开关也不能替代迁移。若临时 export 了迁移专用 DATABASE_URL，结束后 `unset DATABASE_URL`，并确认服务自己的连接配置正确。
4. API 配置同时启用：

```dotenv
WECHAT_BOT_PRIVATE_SCORE_ENABLED=true
WECHAT_BOT_PRIVATE_MANAGEMENT_ENABLED=true
```

两个开关默认关闭。关闭管理开关停止新的晋级、转会、拍卖私聊操作，不撤销已完成业务；保留迁移。新版群管理入口始终拒绝操作，灰度期间需要在后台管理拍卖。

5. Windows 在提交已推送后更新，无需改现有设备 ID、令牌或 bridge.toml：

```powershell
cd D:\workspace\efootball_management
git pull --ff-only origin dev
cd apps\wechat-bridge
uv sync --extra windows
uv run efm-wechat-bridge --config .\bridge.toml doctor
New-Item -ItemType Directory -Force .\logs | Out-Null
$bridgeLog = ".\logs\private-management-$(Get-Date -Format yyyyMMdd-HHmmss).log"
uv run efm-wechat-bridge --config .\bridge.toml run --enable-send 2>&1 | Tee-Object -FilePath $bridgeLog
```

## 私聊命令

先发送 `帮助`。多联赛管理员先 `联赛` → `切换联赛 名称或ID`；必要时 `赛季` → `切换赛季 名称或ID`。沿用后台已有管理员绑定，无需验证码。

| 用途 | 示例 |
| --- | --- |
| 查询比赛短号 | `赛程`、`赛程 2` |
| 人工裁定杯赛晋级 | `晋级 M12 客队 原因：主队弃权` |
| 查询球队 | `球队` |
| 查询球员归属短号 | `阵容 T1` |
| 转会 | `转会 P3 T1 T2 500 原因：双方确认` |
| 查询拍卖批次 | `拍卖列表` |
| 查询拍品及分页 | `拍卖 A5`、`拍卖 A5 2` |
| 开始拍卖 | `开始拍卖 A5` |
| 紧急暂停（立即生效） | `暂停拍卖 A5` |
| 继续正常暂停的拍卖 | `继续拍卖 A5` |
| 取消批次 | `取消拍卖 A5 原因：重新安排` |
| 故障后的人工恢复 | `恢复拍卖 A5 原因：已核对群消息` |
| 确认系统拍卖结果 | `审核成交 L8` |
| 调整成交球队与价格 | `调整成交 L8 T2 500 原因：核对最终报价` |
| 作废成交 | `作废成交 L8 原因：出价无效` |

编号必须用机器人实际返回值：M 是比赛、P 是球员归属、A 是拍卖批次、L 是拍品；T 是当前联赛球队编号。金额为与后台一致的整数系统单位，不接受小数。

除紧急暂停外，机器人先返回联赛、赛季、对象和执行效果。**2 分钟内私聊 `确认 确认码` 才提交**；`取消 确认码` 放弃，`操作 确认码` 查看回执。同一确认码重复确认只返回已完成结果，不重复结算。

- 晋级只支持已发布的杯赛淘汰对阵，明确指定系统主队或客队，原因必填。不伪造比分；签表、赛程显示“裁定晋级（无比分）”。下一轮已经报分时不能更改胜者，有活跃比分争议时先在后台处理。后续录入正式比分会清除人工晋级标记并重新推进签表。
- 转会仅操作联赛当前赛季、现役球队，沿用转会窗口、球员归属、工资帽、人数、手续费和账目规则。预览展示实际费用与转入工资；确认时规则或结果发生变化会整体回滚，要求重新预览。
- 拍卖管理仅针对本机器人绑定群、当前联赛的微信群拍卖。批次创建、球员配置和准备仍在后台完成；小程序拍卖渠道仍在后台管理。本期支持开始、暂停、继续、取消、故障恢复、审核/调整/作废成交。
- 无人出价的提名拍品复用已有后台规则：审核时重新核对有效首位提名者及底价入队条件；不会把无效提名强行入队。
- 恢复与普通继续分开。设备在线、已登录、未锁屏、熔断已复位，且目标群没有正在发送或结果不确定的发件，才允许恢复并重新倒计时 30 秒。仅复位设备熔断不代表旧发件已核对；不确定任务需要先按故障处理流程查清，不能自动重发。
- 开拍、暂停、继续、取消、恢复和审核公告只进入批次绑定群；管理员预览与回执在私聊。过长公告分段发送。

## 验收与边界

使用隔离数据库及专用测试群，不在共享联赛造测试记录。先单条验证，再验证持续运行：

1. 预览晋级，后台签表不变；确认后无假比分且下一轮正确。尝试改动已报分下游的胜者应被拒绝。
2. 预览转会，归属与账目不变；确认后归属、工资、费用一致。重复确认只产生一笔交易；规则变动后的旧确认不得提交。
3. 后台准备批次，管理员私聊开拍；球队负责人只在群里出价。普通用户私聊或群聊发送管理命令不能写入。
4. 验证暂停、继续、取消与恢复。故障任务未核对时不得恢复；故障恢复后保留竞价记录，重新倒计时。
5. 审核、调整或作废成交，检查账目与阵容只结算一次。撤销管理员联赛授权、解绑或停用账号后旧确认失效。
6. 将微信停留在别的群，确认所有公告只发到拍卖绑定群。保存 Bridge 日志，检查服务端回执和队列。实际 Windows 窗口定位及发送确认仍需实机验收。

实现说明：预览在同一业务事务的保存点内执行真实校验后回滚；确认时再次执行业务并比较费用/结果快照，业务、审计、回执与群公告一起提交。MySQL 保存点不能使用 prepared statement 协议，因此 Prisma MariaDB adapter 使用其官方 `useTextProtocol` 选项，参数仍由驱动转义。相关真实数据库 API 回归覆盖此配置。

本次开发仅迁移了本机隔离验证库。目标环境 `pnpm db:status` 返回 Schema engine error，目标迁移、接口与实际 Windows 微信发送尚未验收，不应直接开启开关承接日常操作。
