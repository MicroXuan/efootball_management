# PESDATA 每日对账：本机 5 万卡扫描基准

2026-10-23 在隔离的本机 `efootball_catalog_verify` MySQL 库运行。脚本只接受 `localhost` / `127.0.0.1` 且库名包含 `test` 或 `verify` 的显式 `DATABASE_URL`。

## 方法

用 50,000 个合成卡片编号模拟来源列表，每页 100 张，连续写入两遍共 1,000 页、100,000 条扫描记录，再调用数据库内的完整性与双遍集合校验。计时不含真实 PESDATA 网络请求、详情复核、导入批次和版本发布。

命令：

```bash
DATABASE_URL='mysql://efm:efm_local@127.0.0.1:3307/efootball_catalog_verify' \
  pnpm --filter @efm/api exec tsx scripts/benchmark-pesdata-reconciliation.ts
```

## 结果

| 项目 | 本机结果 |
| --- | ---: |
| 第一遍 50,000 张 | 3.88 秒 |
| 第二遍 50,000 张 | 3.71 秒 |
| 数据库完整性与集合校验 | 0.067 秒 |
| 观测到的最高 Node 堆内存 | 242.9 MiB |
| 暂存规模 | 1,000 页、100,000 个卡片编号 |

此结果只证明本机数据库扫描暂存能按页执行；实际每日耗时主要取决于官网请求限速、重试和新增卡详情数量。不得把 7.6 秒当成生产同步耗时或小程序查询延迟。

## 数据清理与上线限制

脚本在删除前按精确运行 ID 核对记录并备份到 `/tmp/efm-reconciliation-benchmark-3ba00cca-2e1f-4786-9727-be9329c189e6.ndjson`，随后在事务内删除合成任务、来源和管理员。复查：该运行的扫描记录从 100,000 条降至 0；测试来源、管理员和用户前缀残留均为 0。

每天两遍 50,000 张会增加约 100,000 条暂存记录。当前版本保留扫描证据以支持相邻两日下架复核与审计；长期存储需要按**精确运行 ID**先归档、预览与备份，再按项目数据安全约束事务清理。上线前应在目标环境核对迁移、索引、磁盘容量和首轮真实扫描结果，初始保持定时任务关闭。
